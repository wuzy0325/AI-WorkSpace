# DAQ-P-1604 v0.3.0

Release date: 2026-07-03
Package: daq-p1604-0.3.0-amd64-installer.exe

## Summary

CSV 录制改为**每设备一个文件**。原单文件设计在多设备同时录制时，两台设备的硬件时间戳交替跳跃写入同一 CSV 文件，时间戳列在两个值之间来回跳变（实测差 26 秒），数据列也混杂。本次按 deviceId 路由到独立文件，与 wind-daq 设计对齐。

## User-visible Changes

- 多设备同时录制时，每台设备生成独立的 CSV 文件，文件名包含设备名，便于辨识。
- 文件名格式变更：
  - 旧：`<prefix>_YYYYMMDD-HHMMSS.csv`
  - 新：`<prefix>-<deviceSlug>-YYYYMMDD-HHMMSS-NNN.csv`
  - 示例：`DAQ-P1604-风洞主设备-20260703-153852-001.csv`
- 单设备录制行为不变（仍生成一个 CSV），仅文件名格式调整。

## Fixes

- 修复多设备同时录制时 CSV 时间戳在两个值之间交替跳变的问题（根因：两台设备硬件时钟未同步，单文件混杂写入）。

## Internal

- `CSVRecorder` 重构为多 writer 架构：`map[deviceId]*perDeviceWriter`，每设备独立持有文件/缓冲/统计。单 writer goroutine 串行消费 channel 消除多设备锁争用。
- `core.RecordingConfig` 新增 `DeviceNames map[string]string` 字段，由 backend 在 StartRecording 时从 profiles 一次性填充 deviceId→name 映射，recorder 用于生成人类可读的文件名 slug。
- `backend/app.go` 的 `StartRecordingWithConfig` 调整为：先取 profiles → 聚合通道精度 → 构建 deviceNames map → 注入 RecordingConfig。
- 文件滚动条件（MaxSize/MaxRecordCount/MaxDuration）改为按设备独立评估，停止条件（跨设备汇总）保持不变。
- 录制启动时不再预创建空文件，改为第一个 payload 到达时按 deviceId 懒创建，避免多设备场景下未投递数据的设备产生空 CSV。
- 清理 dead code：移除未消费的 `autoDone`/`autoDoneOnce`/`signalAutoDone` 信号机制，以及 `perDeviceWriter` 的 `deviceID`/`headerWritten`/`totalRecords` 三个未读字段。
- 同步 6 个版本号文件到 0.3.0：`VERSION`、`apps/desktop-wails/wails.json`、`apps/desktop-wails/frontend/package.json`、`apps/desktop-wails/frontend/package-lock.json`、`apps/desktop-wails/build/config.yml`、`apps/desktop-wails/build/windows/installer/project.nsi`。

## Compatibility

- 配置文件格式：兼容，无需迁移。
- **数据文件格式：不兼容**。CSV 文件名格式变更（`_` 分隔符改为 `-`，新增 deviceSlug 和序号后缀），用户脚本/工具若依赖旧文件名格式需适配。CSV 内部列格式（`Timestamp,CH01..CH16,CH17_AtmPressure,CH18_AtmTemp`）保持不变。
- 设备协议行为：无变化。

## Install / Upgrade

- 支持覆盖安装，无需先卸载旧版本。
- 推荐步骤：
  1. 关闭正在运行的旧版本。
  2. 运行 `daq-p1604-0.3.0-amd64-installer.exe`。
  3. 启动新版本并确认 GUI 正常出现。
  4. （可选）实机验证：连接两台 DAQ-P-1604 同时录制，应生成两个独立 CSV 文件，文件名包含各自设备名，时间戳不再交替跳变。

## Known Issues

- DAQ-P-1604 设备固件时间戳 bug 仍存在（fractional 字段以 ~4348Hz 递增），CSV 时间戳已统一截断到秒级规避。根本修复需联系硬件厂商。
- 多 writer 核心路由逻辑（`getOrCreateWriter` / `sanitizeFileSegment` / `uniqueFileSlugLocked` / `shouldRotate(deviceID)`）暂无单元测试覆盖，依赖实机多设备验证。

## Rollback

- 可回退到 0.2.4。配置文件格式兼容；CSV 文件名格式不兼容但旧版本会按自身格式生成新文件，不影响旧版本正常运行。

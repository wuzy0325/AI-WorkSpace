# DAQ-P-1604 v0.7.3

Release date: 2026-07-31
Package: daq-p1604-0.7.3-amd64-installer.exe

## Summary

本版本将 ADR-009 watchdog 硬兜底机制从 `sendCommandACK` 扩展到设备发现（discovery）链路，统一 adapter IO 错误处理（毒化连接 + sentinel 错误），并修复 Stop transaction 在 soft deadline 触发后无法可靠取消的问题。这是 0.7.2 的 watchdog 兜底在 discovery 与 Stop 流程上的对称补强，进一步覆盖 Windows 网络栈 `SetReadDeadline` 失效场景。

## User-visible Changes

- 设备发现（扫描）界面在 Windows 网络栈异常时不再可能永久阻塞，watchdog 到期后必返回错误。
- Stop 采集命令在 soft deadline 触发后能强制关闭连接并向上返回明确的 sentinel 错误，调用方驱动会被毒化并触发重建，避免在已失效连接上继续重试。
- 现场日志中 discovery 阶段的 `Read`/`Receive` 永久阻塞类问题消除。

## Fixes

- **discovery 永久阻塞（ADR-009 finding 5）**：跨平台 `discovery_socket.go` 的 Send/Receive 加 `SetDeadline` + 独立 watchdog timer 双兜底；Windows `discovery_socket_windows.go` 的 `winsockDiscoverySocket` 加 `handleMu` 保护 handle，`closeHandleLocked` 原子取走 handle，`startWatchdog` 返回 stop-and-join，避免 callback 在操作返回后误关已复用 socket 数值。
- **Stop transaction soft deadline 后无法取消**：`StopAcquisition` 改用 `context` 控制总预算，soft deadline 触发时强制 `Close(conn)` 并返回 `ErrWatchdogTriggered` sentinel，调用方毒化驱动并重建连接。
- **adapter IO 错误处理不统一**：适配 `shared/device-sdk/go/protocol` 层的 `wrapP1604IOError` / `ErrWatchdogTriggered`，soft deadline 触发时强制 Close conn 并返回 sentinel 让调用方毒化驱动，避免后续命令在已失效连接上重试。
- **跨项目 watchdog 实现重复**：删除本地 `watchdogClose` 函数，改用 `shared/device-sdk/go/protocol.WatchdogClose` 统一 ADR-009 watchdog 实现。
- **`expectedConn` 比较误杀新连接**：与 daq-t1603 B140 同款 finding 2 修复，Stop transaction remediation 测试中 `expectedConn` 比较避免误杀重建后的新连接。

## Compatibility

- 配置文件格式兼容。
- CSV 数据格式不变。
- 设备协议命令链（`w1601` / `c 00` / `c 05` / `c 01` / `c 02` / `h`）不变。
- discovery 协议（UDP 广播 + 单播响应）不变，仅加 watchdog 兜底。
- 删除 `p1604ConsecutiveTimeoutThreshold`（25 次 5s 超时）与 `p1604CommandResponseTimeout`（合并入 `p1604HandshakeTimeout`），原应用层断线检测由 ADR-009 watchdog + TCP keepalive 兜底，行为等价或更可靠。

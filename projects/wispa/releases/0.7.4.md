# DAQ-P-1604 v0.7.4

Release date: 2026-08-04
Package: daq-p1604-0.7.4-amd64-installer.exe

## Summary

修复扫描弹窗内联改名不生效（用户改名被静默丢弃，设备始终使用默认名），并在设备配置面板新增设备名修改入口与改名唯一性校验，与扫描路径的 `dedupeName` 约束对齐，避免 sidebar/monitor 出现多个同名设备无法区分。

## User-visible Changes

- 扫描弹窗中内联修改的设备名现在会真正生效（此前因字段名不匹配被静默丢弃，设备始终使用按 MAC/IP 生成的默认名）。
- 设备配置面板"硬件参数" section 顶部新增"设备名称"输入框，用户可随时改名（采集期间禁用，与采样频率等硬件参数一致）。
- 改名保存时校验名字唯一性：若与其它设备重名，阻断保存并提示"设备名称已被其他设备占用，请修改后重试"。

## Fixes

- **扫描弹窗改名不生效**：`ScanResultList` 的 `ScanSelectionItem.name`（UI v-model 字段）与 `ScannedDeviceInput.overrideName`（`planScannedAdditions` 期望字段）字段名不匹配。`AppShell` 把 `scanSelection` 原样传入 `addScannedProfiles`，TS 结构子类型不报错，但运行时 `input.overrideName` 永远 `undefined`，永远回退到 `makeDefaultName`。修复：将 `ScannedDeviceInput.overrideName` 改名为 `name`，与 `ScanSelectionItem` 对齐，UI v-model 数据可直接透传，消除字段映射层。
- **配置面板缺少设备名修改入口**：`DaqP1604Config.vue` 头部只读显示 `profile.name`，整个面板没有设备名 input，`saveConfig` 也不写 `name` 字段。修复：新增 `deviceName` ref，在 `syncFormFromProfile` 回填、`formEqualsProfile` 脏值比较（trim 后比对）、watcher 监听、`saveConfig` 写入 `nextProfile.name`；改名不触发 `applyConfig`（`hasHardwareConfigChanged` 不含 name），只走 `saveProfile` 持久化。
- **改名缺少唯一性校验**：扫描路径 `planScannedAdditions` 通过 `dedupeName` 保证名字唯一，但新增的配置面板改名路径走 `saveProfile` 仅按 `id` 替换，不校验名字是否与其他 profile 重复。修复：`saveConfig` 开头加唯一性校验，与扫描路径的 `dedupeName` 约束对齐。批量扫描用无感追加 `(2)/(3)`，配置面板显式改名阻断并提示，两条路径行为互补。

## Compatibility

- 配置文件格式兼容（`PressureProfile.name` 字段类型不变）。

# DAQ-T1602 温度扫描阀 LabVIEW 逻辑解析

> 本文档由 3 张 LabVIEW 源码截图逆向解析而成，用于指导后续 Go / 上位机重写。
> 设备为**温度扫描阀**，机内含 **2 张采集卡**，每卡 8 通道，合并为 16 通道单设备对外。
> 通信协议：**Modbus TCP**。

---

## 一、设备物理结构（用户确认）

```
┌─────────────────────────────────────────────┐
│            DAQ-T1602 温度扫描阀              │
│  IP: x.x.x.x   端口: 502                    │
│                                             │
│  ┌──────────────┐    ┌──────────────┐       │
│  │   采集卡 1   │    │   采集卡 2   │       │
│  │  Slave ID = 1│    │  Slave ID = 2│       │
│  │  CH 0 ~ CH 7 │    │  CH 0 ~ CH 7 │       │
│  └──────────────┘    └──────────────┘       │
│        ↑                     ↑              │
│    session1              session2           │
│    (寄存器地址与卡2相同，通过 Slave ID 区分)  │
└─────────────────────────────────────────────┘
```

| 项 | 说明 |
|---|---|
| 通道总数 | 16（卡1: 0~7，卡2: 0~7） |
| 卡间关系 | 两卡寄存器地址完全相同，靠 Slave ID 区分 |
| 通信方式 | Modbus TCP，同一 IP + 端口 502（实测，非 5000） |
| 会话数 | 2 条独立 TCP 会话（Slave ID 1 / 2） |
| 超时 | 5000 ms |
| 实测单次读上限 | 8 寄存器（读 9+ 返回 Modbus 异常码 2） |
| 实测响应节流 | 单请求 RTT 固定 ~103ms，请求串行处理 |

## 二、三个 VI 逻辑详解

### 2.1 open device.vi —— 建立连接

**职责**：向同一设备 IP 建立两条独立的 Modbus TCP 会话。

**流程**：
1. 输入 IP 地址、端口 502、超时 5000ms。
2. 创建 **session1**：Slave ID = 1（对应采集卡 1）。
3. 创建 **session2**：Slave ID = 2（对应采集卡 2）。
4. 两条会话独立保持，后续读类型 / 读数据都复用。

**关键点**：
- 两条会话指向**同一 IP 同一端口**，仅 Slave ID 不同。
- 不在此处做任何数据读取，纯粹建立通道。

---

### 2.2 read channel type.vi —— 读取热电偶类型

**职责**：读取 16 个通道各自的热电偶分度号配置。

**寄存器映射**：

| 通道 | 物理卡 | Slave ID | 保持寄存器地址 |
|---|---|---|---|
| CH 0 ~ CH 7 | 卡 1 | 1 | 200 ~ 207 |
| CH 8 ~ CH 15 | 卡 2 | 2 | 200 ~ 207 |

> 两卡的寄存器地址相同（都是 200~207），通过 Slave ID 路由到不同物理卡。

**流程**：
1. For Loop 循环 **16 次**（对应 16 通道总数，2 卡 × 8 通道）。
2. 每次读取一个保持寄存器（Holding Register），得到该通道的 Type Code。
3. 前 8 次用 session1（Slave ID 1）读卡 1 的 200~207。
4. 后 8 次用 session2（Slave ID 2）读卡 2 的 200~207。
5. 输出 16 元素的 Type Code 数组。

**Type Code 枚举值**（从 0 开始）：

| Type Code | 热电偶分度号 |
|---|---|
| 0 | J |
| 1 | K |
| 2 | T |
| 3 | E |
| 4 | R |
| 5 | S |
| 6 | B |
| 7 | N |

---

### 2.3 acq data.vi —— 采集数据

**职责**：同时读取 16 通道原始 AD 值，按热电偶类型做量程线性转换，输出物理温度。

**寄存器映射**：

| 通道 | 物理卡 | Slave ID | 输入寄存器地址 |
|---|---|---|---|
| CH 0 ~ CH 7 | 卡 1 | 1 | 0 ~ 7 |
| CH 8 ~ CH 15 | 卡 2 | 2 | 0 ~ 7 |

> 注意：类型寄存器从 200 开始，数据寄存器从 0 开始，两卡地址相同靠 Slave ID 区分。

**流程**：
1. session1 读取卡 1 的输入寄存器 0~7 → 得到 CH0~CH7 原始值（8 个）。
2. session2 读取卡 2 的输入寄存器 0~7 → 得到 CH8~CH15 原始值（8 个）。
3. 合并为 16 通道原始值数组。
4. 对每个通道，用其 Type Code 索引量程表（range list），取出 `[min, max]`。
5. 线性转换：`物理值 = raw / 65535 × (max - min) + min`。
6. 输出 16 通道物理温度值。

**量程表（range list）**：

总共 10 行，行号 = Type Code，8/9 行未使用（用户提供，2026-08-13 真机交叉验证）：

| Type Code | 热电偶 | 量程 [min, max] ℃ |
|---|---|---|
| 0 | J | (-50, 50) |
| 1 | K | (0, 1200) |
| 2 | T | (0, 1300) |
| 3 | E | (-200, 400) |
| 4 | R | (0, 1000) |
| 5 | S | (0, 1700) |
| 6 | B | (0, 1768) |
| 7 | N | (0, 1800) |
| 8 | （未使用） | (-200, 800) |
| 9 | （未使用） | (-2000, 1000) |

> ✅ 已验证（2026-08-13）：K 型通道 raw 1513 → 27.7℃ 与室温吻合；T 型配置
> raw 1369 → 27.2℃ 交叉一致；无信号通道 raw=0 表示未接入（上位机显示"--"）。注意行序与教科书
> 标准量程不对应（如 code 3=E 配 (-200,400)），以设备固件实际表为准。
> （早期版本曾误用教科书标准量程，导致室温解出 -256℃ 的荒谬值。）

## 三、数据转换公式

```
物理温度(℃) = raw / 65535 × (RangeMax - RangeMin) + RangeMin
```

| 参数 | 说明 |
|---|---|
| `raw` | Modbus 输入寄存器读到的 16 位无符号原始值（0~65535）；**0 = 通道未接入热电偶**（开路输出，2026-08-13 用户确认），上位机应显示"未接入"而非量程下限温度 |
| `65535` | 满量程除数（16 位 ADC 最大值） |
| `RangeMin` / `RangeMax` | 由 Type Code 索引量程表得到 |

**示例**：K 型热电偶，量程 `[0, 1200]`（用户提供表），raw = 32768：
```
温度 = 32768 / 65535 × (1200 - 0) + 0 ≈ 600.1 ℃
```

1. **量程表 10 行的具体数值** —— ✅ **已确认（用户提供 2026-08-13 + 真机交叉验证）**，见上文 §2.3。
2. **Type Code 是否有校验** —— 未实测。当前设备 16 通道 Type Code 均为 2（T 型），无异常。
3. **原始值是否有符号** —— 未确认。按无符号 0~65535 处理。
4. **采集触发方式** —— 未确认。
5. **采样率配置** —— 未确认。
6. **冷端补偿（CJC）** —— 未确认，需确认设备内部已补偿还是上位机需处理。

## 六、实测记录（2026-08-12，设备 192.168.3.201）

### 6.1 连接信息

| 项 | 值 |
|---|---|
| IP / 端口 | 192.168.3.201 / **502**（文档原写 5000，实测为 502） |
| 物理结构 | 1 个 IP、2 张独立采集网卡，Slave ID 1 / 2 区分 |
| 连接 | 两条独立 Modbus TCP 会话均可同时建立 |

### 6.2 寄存器实测

| 查询 | Slave 1 | Slave 2 |
|---|---|---|
| FC3 保持寄存器 200~207（类型） | 全部 = `0x0002`（T 型） | 全部 = `0x0002`（T 型） |
| FC4 输入寄存器 0~7（数据） | `[0, ~1395, 0,0,0,0,0,0]`（仅 CH1 有值） | 全部 = `0x0000` |

- 类型寄存器全部为 2 = T 型热电偶。
- 仅通道 1（CH1）接入热电偶，raw ≈ 1392~1398 波动；其余通道无信号为 0。
- raw = 1395 时按早期误用的教科书标准 T 量程 (-270,400) 换算得 -255.7℃（荒谬值）。
  ✅ **2026-08-13 定案**：设备固件实际 T 型量程为 (0,1300)（用户提供表），
  `1395/65535 × 1300 ≈ 27.7℃`，与室温吻合；K 型通道（raw 1513，量程 (0,1200)）
  同法得 27.7℃，交叉一致。公式 `raw/65535×(max-min)+min` 经用户确认无误。

### 6.3 测速结果

| 方式 | 速率 | 结论 |
|---|---|---|
| 单连接顺序读双卡 | 4.9 Hz | 16 通道完整采集 |
| 单连接流水线（并发发请求） | 4.9 Hz | 无提升 |
| 双连接并行读两卡 | 4.9 Hz | 无提升 |

**并行时序实证**：同一时刻双连接并行发请求，Slave 1 恒 ~103ms 返回，Slave 2 恒 ~206ms 返回——第二个请求被排队等第一个的 100ms 周期完成。

**瓶颈结论**：固件单一串行处理路径，两张卡物理独立但响应串行。16 通道完整采集硬上限 ~4.9 Hz，任何上位机并发策略无法突破。

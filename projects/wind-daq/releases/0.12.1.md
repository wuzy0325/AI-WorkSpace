# Wind-DAQ v0.12.1

Release date: 2026-08-03
Package: wind-daq-0.12.1-amd64-installer.exe

## Summary

针对 LSP/安全软件（Astrill ASProxy64.dll、深信服驱动等）hook winsock 导致 SetReadDeadline 失效、conn.Close() 永久阻塞的故障模式，完成设备网络操作防本机卡死整改；并修复七孔校准区域归属改用预设配置替代压力判定（依赖压力值判定的 7 孔状态可能在低压力场景误判）。

## User-visible Changes

- **退出流程兜底**：用户确认退出后 30s 强制定时器，优雅关停卡死时强制结束进程，不再无限挂起"未响应"。
- **设备扫描/操作超时提示**：设备扫描与设备/运动管理操作有 10s 有界等待，底层被 LSP 卡死时前端返回"操作超时（底层可能无响应），请重试"提示，按钮不再永久转圈。
- **本地 API 端口占用显性提示**：127.0.0.1:8900 被另一 Wind-DAQ 实例占用时弹出错误对话框并停止启动本地服务，替代原先静默失败导致前端轮询卡死。
- **七孔校准区域归属**：改用预设配置判定区域，不再依赖压力值判定，低压力/零压场景下区域不再误判。
- **卡死诊断**：退出关停任一步骤超过 5s 时自动 dump 全 goroutine 栈到 `%APPDATA%\wind-daq\goroutine-dump-<时间戳>.txt`。

## Fixes

- 设备网络操作防本机卡死整改（LSP 环境加固）：
  - `WatchdogClose` 语义重构：timer 回调 go AbortConnection（CloseWrite FIN + Close），wdStop 不再等待 Close 完成。
  - `wtnmc4a_motion` FFI 调用全部改走 ffiGate（单 worker + 有界投递等待 + 超时失败），杜绝 DLL syscall 阻塞冻结控制器锁。
  - 驱动层（p1064pre/p1604/dsa3217/wtn_pxi）同步 Close 改后台 detach；扫描链 closesocket 移出 handleMu、scanInFlight 增加 8s deadline + 超时重置。
  - `device_manager` 全局锁内网络 I/O 移出（SetUnit/ApplyConfig 等改锁外执行）。
  - API server Shutdown 改后台 goroutine + 主线程 300ms 有界等待，退出流程不再卡在 listener cancelIO。
- 修复 `UpsertProfile` 锁外 SetUnit 后旧索引 TOCTOU（重取锁重新定位），并补回归测试。
- 修复前端 wails-adapter 静态导入 Events 问题导致的退出确认事件不注册。

- 数据文件格式：兼容。
- 设备协议行为：无变化。
- API 契约：兼容，无 backend 方法签名变更。

## Install / Upgrade

- **从 0.12.0 升级**：直接运行 `wind-daq-0.12.1-amd64-installer.exe` 覆盖安装，用户数据不存储在安装目录，升级无数据丢失风险。
- **全新安装**：运行 `wind-daq-0.12.1-amd64-installer.exe`。
- 推荐步骤：
  1. 关闭正在运行的旧版本。
  2. 运行 `wind-daq-0.12.1-amd64-installer.exe`。
  3. 启动新版本并确认 GUI 正常出现。

## Known Issues

- 安装包未进行 Authenticode 数字签名，Windows 可能显示未知发布者提示。
- LSP 拦截场景下底层操作超时后为受控降级（前端提示重试），卡死 goroutine 随进程退出释放；不影响正常环境。

## Rollback

- 卸载 0.12.1：通过"控制面板 → 程序和功能"卸载。
- 回退到 0.12.0：运行 `wind-daq-0.12.0-amd64-installer.exe` 重新安装。

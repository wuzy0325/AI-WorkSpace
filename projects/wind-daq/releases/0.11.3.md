# Wind-DAQ v0.11.3

Release date: 2026-07-31
Package: `wind-daq-0.11.3-amd64-installer.exe`

## Summary

本版本完成双探针遍历（dual traversal）后端 registry 与 lease 端口体系建设，落实 ADR-009 网络扫描器分平台 watchdog 整改，并完成 i18n 国际化抽取工作（dual 错误文案字典、安全占位符替换、七孔图表 i18n 完整覆盖）。同时修复 0.11.2 发布后发现的若干问题（双探针遍历 dashboard 设备流断开、实时结果数据源错位、七孔校准波形图算法、状态栏冗余 Ma/V 显示、插值状态栏布局抖动、NSIS 脚本缺 UTF-8 BOM）。

## User-visible Changes

- 双探针遍历模式后端架构升级：引入 `ManagerRegistry` 提供 probe-scoped 生命周期管理，每探针一套独立 goroutine，单探针的 Start/Stop/Pause/Resume 串行化但**不阻塞其他探针**；两个探针可分别 lease 同一控制器的不同物理轴（如 probe1 用 X 轴、probe2 用 Y 轴挂同一 B140），仅 `(controllerID, axis)` 元组粒度判定冲突。
- 双探针遍历模式新增 lease 续约/释放安全机制：opaque lease token 保证旧 generation 在 lease 被新 session 接管后无法续约或释放，避免陈旧回调误释放新 session 的 lease。
- 双探针遍历模式新增 checkpoint 恢复索引：stopped/error 终态保留 checkpoint 映射，completed 注销，Stat 失败或文件不存在时注销 stale 映射；不变量"映射存在 ⟺ checkpoint 文件存在"。
- UDP 设备发现新增 Windows raw winsock 分平台实现（`SO_SNDTIMEO` + 独立 watchdog + stop-and-join 语义），落实 ADR-009 "永远不要把 socket deadline 作为有界硬件 I/O 的唯一取消机制"。Windows 下 `SetReadDeadline` / `SO_RCVTIMEO` 在故障机器上可能因 kernel IOCP deadline 失效而永久阻塞，独立 owner 调用 `conn.Close()` 是唯一可靠解阻塞手段。
- WTN-PXI 设备新增 10s 无数据 timer：网络中断/设备断电/网线脱落/服务端崩溃时即使 Read 永久阻塞也能到期触发。
- DAQ-P-1604Pre 默认 host/port 修正为实测值（`192.168.3.232:23`），命令码 `CMD_ACQUISITION_CTRL` 修正为 `0x14`（旧值 `0x10` 设备不识别）。
- 七孔校准各区波形图完成 i18n 完整覆盖（轴名 / tooltip / legend / 标题全部走 i18nStore）。
- 七孔校准顶部状态栏不再冗余显示马赫数/速度（与侧边栏重复）。
- 遍历视图插值状态栏不再因 `interpStatus` 切换产生高度跳变。
- NSIS 安装脚本添加 UTF-8 BOM，避免手动调用 makensis 时解析失败。

## Fixes

- 双探针遍历 dashboard 设备流在 dual 页面切换时被错误断开（`deviceStore` 引用计数）。
- 双探针遍历实时结果只来自后端 `latestData` 而忽略 DAQ 快照：改为以 DAQ 快照为唯一实时数据源，`latestData` 仅在测点完成时提供权威插值结果。
- 双探针遍历 `dualTraversalRuntime` 高频 snapshot 节流间隙请求堆积导致结果闪烁（`realtimeInFlight` 守卫）。
- 双探针遍历 pause/resume 乐观更新期间陈旧轮询回退状态造成 UI 闪烁（`optimisticStatusUntil` 窗口）。
- 七孔校准各区波形图算法错误（图表数据序列错位、tooltip 显示异常）。
- 七孔校准顶部状态栏冗余显示马赫数/速度。
- 遍历视图插值状态栏 `interpStatus` 切换时高度跳变。
- NSIS 安装脚本缺 UTF-8 BOM 导致手动调用 makensis 解析失败。
- 五孔探针校准 `AcquireData` 旧入口缺少通道配置时静默返回零值导致 `Kα=0 / Kβ=0 / CPT=0` 无告警：现直接返回错误，强制走 `AcquireDataWithConfig` / `AcquireDataWithChannels`。

## Compatibility

- 配置文件格式：兼容。DAQ-P-1604Pre 默认 host/port 变化仅影响新发现设备写入的默认值，旧 profile 已保存的 host/port 不受影响。
- 数据文件格式：兼容。dual traversal checkpoint 仅接受 v3，v1/v2 不自动迁移（返回 `ErrCheckpointVersionMismatch`），legacy 单探针 checkpoint 路径不动。
- 设备协议行为：DAQ-P-1604Pre `CMD_ACQUISITION_CTRL` 命令码修正为 `0x14` 是 bug 修复（旧值设备不识别），非破坏性变更。
- API 契约：
  - `Deps` 结构体新增 `TraversalRegistry` 字段，外部装配点需补字段（生产装配由 composition root 注入，影响有限）。
  - `FiveHoleAlgorithm.AcquireData` 直接返回错误而非零值，强制走 `AcquireDataWithConfig`，外部调用方需迁移。
  - dual 路径仅接受 v3 checkpoint，旧客户端提交的 taskID 不再成为权威 ID（服务端经 `TaskIDGenerator.NewTaskID` 生成），已存旧客户端 taskID 的持久化数据不受影响，但新 dual 启动会覆盖。

## Install / Upgrade

- 兼容覆盖安装，无需先卸载旧版本。
- 推荐安装步骤：
  1. 关闭正在运行的旧版本 Wind-DAQ。
  2. 运行 `wind-daq-0.11.3-amd64-installer.exe`，选择安装语言（中文/英文）。
  3. 按向导完成安装，安装程序会自动检测并安装 WebView2 Runtime（如未安装）。
  4. 启动 Wind-DAQ，确认 GUI 正常出现，进入双探针遍历页面验证 dual registry 与 lease 端口工作正常。

## Known Issues

- 安装包未进行 Authenticode 数字签名，Windows 可能显示未知发布者提示。
- dual traversal checkpoint 仅支持 v3 格式，不支持 v1/v2 自动迁移。
- UDP 设备发现 Windows raw winsock 实现依赖 `golang.org/x/sys/windows` 私有常量 `0x1005`（`SO_SNDTIMEO`），后续 Windows SDK 升级需关注该常量稳定性。

## Rollback

- 可直接卸载 0.11.3 后安装 0.11.2 回退，配置与数据文件无需处理。
- 如需保留 0.11.2 安装包，`releases/bin/wind-daq-0.11.2-amd64-installer.exe` 仍在归档中。
- 注意：0.11.3 创建的 dual traversal v3 checkpoint 无法在 0.11.2 中加载（dual registry 在 0.11.2 中尚未引入，路径返回 503）。

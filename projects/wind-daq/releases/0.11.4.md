# Wind-DAQ v0.11.4

Release date: 2026-07-31
Package: `wind-daq-0.11.4-amd64-installer.exe`

## Summary

本版本是 0.11.3 发布后 ADR-009 网络可靠性整改的延续 PATCH 版本，落实独立审查 finding 1-9 的剩余整改项（R1-4 DialTCP abandoned 信号、R0-12 ACK soft timeout 毒化、R0-2 watchdog 锁顺序、R0-8/R0-9 UDP discovery 双兜底、R2-1 诊断工具 DialTCP 替换），同时修复 T1603 temp 固件对 `@fe BIN 1` 假成功响应导致的二进制模式同步错位、B140 motion Disconnect 死锁链、`LoadCheckpoint` 在运行态 session 下的状态分裂等问题。

## User-visible Changes

- **T1603 设备严格校验**：`@fe BIN 1` 命令发送后必须重新查询 `@fd BIN` 验证实际模式，应对设备 temp 固件"返回 A 但实际不切换二进制模式"的缺陷。`sendCommand` 对 'E' 响应从"协议错误 + 毒化连接"改为"业务错误 `ErrDeviceRejected` + 不毒化"，区分合法业务层拒绝与协议错位。
- **B140 运动控制器 Disconnect 不再卡死**：原实现先 `sendCommandLocked("ST")` 再 Close，sendCommand 卡死时 Disconnect 等待 connMu 死锁；改为锁内取 conn 引用 + 置 nil，锁外 `conn.Close()`（TCP FIN 足以让 B140 停止运动）。
- **双探针遍历 LoadCheckpoint 状态分裂修复**：registry 仍持有活动 session 时 `LoadCheckpoint` 直接返回 nil，不扫描 recoveryIndex，避免前端同时看到"正在运行"的 session 和"继续/放弃"提示。
- **UDP 设备发现双兜底**：跨平台 `discovery_socket.go` 的 Send/Receive 加 `SetDeadline` + 独立 watchdog timer，Windows raw winsock 实现加 `handleMu` 保护 handle + stop-and-join 语义，避免 callback 在操作返回后误关已复用 socket 数值。
- **T1603 frame 单通道合理帧接受**：`looksLikeReasonableTemperatureFrame` 阈值从 `len(temps)/2`（8 通道）改为 1，适应仅 2 通道接热电偶场景（其余 14 通道为 NaN），消除频繁出现的 "Frame misalignment; resyncing" 警告。
- **诊断工具不卡死**：`p1604-ts-diag` / `p1604-unit-diag` 的 `net.DialTimeout` 替换为 `sharedproto.DialTCP`（goroutine + abandoned 信号 + 软超时），新增 5 分钟进程级硬 watchdog，超时后 `os.Exit(2)` 避免僵尸进程。
- **WTNMC4A FFI proc 名修正**：`getRR1` proc 名从 "WTNMC4A_GetRR1Status" 修正为 "WTNMC4A_GetRR1"（与 DLL 实际导出名一致），原写法在加载阶段会 MustFindProc 失败。

## Fixes

- `DialTCP` 主线程超时返回后晚到 conn 滞留缓冲 channel 导致 FD 泄漏（R1-4 整改：无缓冲 channel + abandoned close 信号）。
- `IsClosedConnError` 未识别 `io.ErrClosedPipe`，导致 net.Pipe 关闭后 readLoop defer 误走 invalidate 路径覆盖 timer 设置的状态。
- T1603 `writeCommandOnly` 中 watchdog 在 `writeMu.Lock` 之后启动导致 SetWriteDeadline 失效时 Write 永久阻塞、所有命令路径死锁（R0-2：watchdog 在 Lock 之前启动）。
- T1603 `applyHardwareConfig` 中途收到 E 错误后本地 cfg 与设备实际模式不一致（新增 `resyncHardwareConfigMode` 重新同步实际 BIN / TIME / HEAD）。
- T1603 `queryBinaryMode` 非 "1" 响应被误判为 "0"，导致 BIN=1 命令失败后仍假定 ASCII 模式。
- T1603 `@fe BIN 1` 命令发送后未重新查询 `@fd BIN` 验证实际模式：设备 temp 固件会返回 A 但实际不切换二进制模式。
- B140 `Disconnect` 在 sendCommand 卡死时等待 connMu 死锁。
- B140 `invalidateConnectionLocked` 在 Disconnect → Connect 替换为新连接后误杀新连接（expectedConn 比较）。
- WTNMC4A `getRR1` proc 名错误导致 MustFindProc 失败。
- daq-t1603 / daq-p1604 `discovery_socket.go` 的 Send/Receive 在 Windows 故障机器 kernel IOCP deadline 失效时永久阻塞（ADR-009 R0-8 / R0-9）。
- daq-p1604 `p1604WatchdogTimeout` 为 const 时测试无法注入短超时加速 deadline-ignore 回归测试。
- wind-daq `LoadCheckpoint` 在 registry 仍持有活动 session 时返回磁盘 checkpoint 造成前端状态分裂。
- 移除 `threehole.interpolate` 薄包装方法与 `makePrbLines` / `formatFloat` 测试 helper（dead code）。
- 移除 `three-hole-interpolator` 孤儿文件 `helpdoc.go`。

## Compatibility

- 配置文件格式：兼容。无新增配置字段，无字段含义变更。
- 数据文件格式：兼容。dual traversal checkpoint 仍仅接受 v3 格式，v1/v2 不自动迁移。
- 设备协议行为：
  - `@fe BIN 1` 命令后新增 `@fd BIN` 验证步骤。**影响**：若设备固件存在该缺陷，原 0.11.3 行为是"假定切换成功 → 后续二进制帧解析失败 → 触发 resync"，0.11.4 行为是"检测到未切换 → 中止同步并返回错误 → 调用方决定重试或报错"。
  - `sendCommand` 对 'E' 响应从"协议错误 + 毒化连接"改为"业务错误 `ErrDeviceRejected` + 不毒化"：调用方需检查 sentinel 错误决定是否重试或上报，不应假定所有错误都触发重连。
- API 契约：兼容。无 backend 方法签名变更，无 frontend bindings 重生成需求。

## Install / Upgrade

- 兼容覆盖安装，无需先卸载旧版本。
- 推荐安装步骤：
  1. 关闭正在运行的旧版本 Wind-DAQ。
  2. 运行 `wind-daq-0.11.4-amd64-installer.exe`，选择安装语言（中文/英文）。
  3. 按向导完成安装，安装程序会自动检测并安装 WebView2 Runtime（如未安装）。
  4. 启动 Wind-DAQ，确认 GUI 正常出现，验证 T1603 / P1604 / B140 设备连接与采集行为。

## Known Issues

- 安装包未进行 Authenticode 数字签名，Windows 可能显示未知发布者提示。
- dual traversal checkpoint 仅支持 v3 格式，不支持 v1/v2 自动迁移。
- UDP 设备发现 Windows raw winsock 实现依赖 `golang.org/x/sys/windows` 私有常量 `0x1005`（`SO_SNDTIMEO`），后续 Windows SDK 升级需关注该常量稳定性。
- `go.work` 当前包含 `./projects/daq-t1603/apps/desktop-wails`，与 AGENTS.md "daq-t1603 excluded from go.work (ADR-006)" 描述存在不一致。若 ADR-006 仍生效需还原 go.work 改动并同步 AGENTS.md；若已撤销需补充 ADR 记录说明。

## Rollback

- 可直接卸载 0.11.4 后安装 0.11.3 回退，配置与数据文件无需处理。
- 如需保留 0.11.3 安装包，`releases/bin/wind-daq-0.11.3-amd64-installer.exe` 仍在归档中。
- 0.11.4 与 0.11.3 的 dual traversal v3 checkpoint 格式一致，可双向加载。

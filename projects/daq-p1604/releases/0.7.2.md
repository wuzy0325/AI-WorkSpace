# DAQ-P-1604 v0.7.2

Release date: 2026-07-28
Package: daq-p1604-0.7.2-amd64-installer.exe

## Summary

本版本修复特定 Windows 环境中开始采集命令卡死、快速启停导致连接被误判故障的两个核心缺陷，统一为采集命令链引入 5s watchdog 硬兜底（ADR-009），并自动跳过 socket 中残留的压力数据帧。

## User-visible Changes

- 现场故障电脑上点击「开始采集」不再卡死，命令链在 5s 内必返回（成功或失败）。
- 快速点击开始/停止采集按钮不再触发连接断开误判。
- 现场日志中 `unexpected command response: "\x01\x00\x00..."` 错误消失。

## Fixes

- **开始采集卡死**：现场一台 Windows 电脑上 `SetReadDeadline` 到期后阻塞 `Read` 仍不返回，导致 `idleReadLoop` 的 `conn.Read` 无法被 `close(stop)` 唤醒，`StartAcquisition` 永久停在第 1 步。
  修复：`idleReadLoop` 改为只等待 stop channel，不再调用 `conn.Read`；彻底放弃依赖 `SetReadDeadline` 保证退出的空闲检测（参考 `docs/acquisition-start-no-response.md` §5.2）。
- **readLoop 残留 deadline 导致快速重启采集失败**：`readLoop` 退出时残留的 200ms deadline 让后续 `sendCommandACK` 的 `ReadFrame` 立即返回 `i/o timeout`（174ms 内重启采集时 23ms 报错）。
  修复：`readLoop` 退出时 `defer SetReadDeadline(time.Time{})` 清除残留 deadline。
- **快速启停残留压力帧污染 ACK 读取**：StartAcquisition 后 60ms 内 StopAcquisition 时，`frameReader` 缓冲区残留压力数据帧，`sendCommandACK("c 02 1")` 的 `ReadFrame` 读到 `"\x01\x00\x00..."` 而非 ASCII `A`，触发误判的 `handleConnectionLost`。
  修复：`sendCommandACK` 重写为循环 ReadFrame 跳过非 ASCII 帧，最多跳 20 帧；超过上限返回 `too many residual frames` 错误避免误报成功。覆盖所有 5 个调用点（StartAcquisition / StopAcquisition / Disconnect / ApplyConfig / ZeroCalibration）。
- **`zeroCalibrationDirect` watchdog 触发时错误信息不一致**：`handleConnectionLost` 和函数返回使用不同 message，前端展示与日志对不上。
  修复：统一为 `zero calibration: read watchdog triggered; reconnect required`。
- **Dead code 清理**：删除 `p1604DrainTimeout` / `p1604IdleCheckInterval` 两个未使用常量。

## Compatibility

- 配置文件格式兼容。
- CSV 数据格式不变。
- 设备协议命令链（`w1601` / `c 00` / `c 05` / `c 01` / `c 02` / `h`）不变。
- 现场已知限制：仅连接不采集时不再有 30~40s 内主动变错误的检测能力；TCP keepalive（3s 间隔，Windows ~33s 检出）仍是兜底，下次命令调用会立即确认连接可用性。

## Install / Upgrade

- 可覆盖安装 0.7.0 / 0.7.1，无需先卸载或清理用户配置。
- 安装前先关闭正在运行的旧版本。
- 运行 `daq-p1604-0.7.2-amd64-installer.exe`，安装后启动应用确认主窗口正常出现。

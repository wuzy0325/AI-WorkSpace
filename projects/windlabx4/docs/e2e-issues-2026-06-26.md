## 已修复并复测通过

### 1. API-Go 启动路径缺少 `/api/motion/*` 路由

- 严重级别：P1
- 现象：Vite 浏览器环境点击运动控制 `连接`、`急停` 等按钮时，请求 `/api/motion/*` 返回 404。
- 根因：`services/api-go/internal/bootstrap.BuildAPIServer` 创建了 motion manager wrapper，但没有把 raw motion manager 作为 `MotionService` 注入 `api.NewRouter`，导致 shared motion HTTP routes 未注册。
- 修复：API-Go 装配 raw motion manager，并设置 `MotionService`。
- 验证：新后端在 `:18080` 执行 `GET /api/motion/status` 返回 `200 []`。
- 状态：已修复。

### 2. Wails 主应用启动后崩溃，导致 `8900` local API 中途消失

- 严重级别：P1
- 现象：运行 `build/bin/wind-daq.exe` 后，应用初始化成功并打印 `Wind-DAQ local API listening on http://127.0.0.1:8900`，随后崩溃。
- 崩溃信息：`panic error: reflect: call of reflect.Value.IsNil on string Value`。
- 崩溃栈：`encoding/json` -> `github.com/wailsapp/wails/v3/pkg/application.(*CustomEvent).ToJSON` -> `DispatchWailsEvent`。
- 根因判断：Wails v3 alpha window JS event 分发触发序列化 bug；当前应用不依赖这些 window JS events。
- 修复：窗口创建后注册 window event hook，并取消 Wails window JS event 分发。
- 验证：桌面主程序启动 9 秒后仍存活，`127.0.0.1:8900/api/motion/status` 返回 200。
- 状态：已修复/规避。

## 本轮已修复，待浏览器 E2E 回归

### 3. 浏览器版运动页非 standalone 模式不会持续刷新状态

- 严重级别：P2
- 现象：点击 `断开` 后，后端 `/api/motion/status` 已确认 `sim-motion-1` 消失，但浏览器页面一度仍显示 `Simulated Controller 1 已连接`。
- 用户影响：连接状态可能与后端真实状态不一致，导致 `连接` 按钮误判为 disabled。
- 相关线索：`MotionControlPanel` 在 `onMounted` 只调用一次 `refreshStatus()`；非 Wails、非 motion standalone 浏览器模式下 `onStatusUpdated` 不启动轮询。
- 修复：`motionApi.onStatusUpdated` 已提供 browser 轮询；本轮补充 `motionStore.connect/disconnect` 后立即 `refreshStatus()`，避免最多 3 秒的连接状态滞后。
- 验证：`npm run typecheck`、`npm run test`、`npm run build` 通过。
- 状态：已修复，待浏览器 E2E 回归确认。

### 4. `storage`、`traversal` 等前端模块默认请求 `127.0.0.1:8900`

- 严重级别：P1
- 现象：当前 Vite + `:8080` 后端配置下，多次出现 `net::ERR_CONNECTION_REFUSED`。
- 失败请求：
- `GET http://127.0.0.1:8900/api/storage/status`
- `POST http://127.0.0.1:8900/api/storage/start`
- `GET http://127.0.0.1:8900/api/traversal/config`
- `GET http://127.0.0.1:8900/api/traversal/status`
- `GET http://127.0.0.1:8900/api/traversal/loadCheckpoint`
- 用户影响：`开始记录`、遍历配置/状态加载等功能在纯 Vite + API-Go 环境下不可用或报错。
- 修复：`otherApis`、`traversalApi` 的 API base 改为显式 `VITE_API_BASE` 优先；Vite dev 默认走相对 `/api` 代理；非 dev Wails 环境保留 `127.0.0.1:8900`。
- 验证：`npm run typecheck`、`npm run test`、`npm run build` 通过。
- 状态：已修复，待 Vite + API-Go E2E 回归确认。

### 5. 页面出现 `404 page not found` 页面错误

- 严重级别：P1
- 现象：E2E 期间多次捕获页面错误 `404 page not found`。
- 可能关联：部分功能按钮点击后请求了当前服务不支持的 API 路径。
- 用户影响：按钮点击后 UI 无法完成操作，控制台出现资源加载失败。
- 修复：本轮修正 storage/traversal/report API base，避免这些模块在 Vite dev 下绕过 `/api` proxy 访问 `8900`。
- 验证：`npm run typecheck`、`npm run test`、`npm run build` 通过。
- 状态：已修复已知前端 API base 来源，待 E2E 网络请求回归确认是否仍有其他 404。

### 6. 设备管理弹窗内 toast 遮挡 `通道设置` 按钮

- 严重级别：P2
- 现象：点击 `新建设备` 后再点 `通道设置`，Playwright 报告 `toast-host` 拦截指针事件。
- 用户影响：toast 显示期间，真实用户也可能无法立即切换到通道设置。
- 修复：toast 从右上角改到右下角；`toast-host` 设置 `pointer-events: none`，单条 toast 保持 `pointer-events: auto` 以允许关闭，不再整块拦截弹窗按钮。
- 验证：`npm run typecheck`、`npm run test`、`npm run build` 通过。
- 状态：已修复，待 E2E 点击回归确认。

### 7. 设置弹窗部分按钮定位到不可见节点或被 modal mask 遮挡

- 严重级别：P2
- 现象：`浅色`、`深色`、`中文`、`English` 定位到不可见节点；`选择` 类按钮被 `n-modal-mask` 拦截。
- 用户影响：自动化测试不稳定；键盘/辅助技术访问也可能不稳定。
- 修复：为设置弹窗主题、语言、选择目录按钮补充明确 `aria-label` 与 `data-test`。
- 验证：`npm run typecheck`、`npm run test`、`npm run build` 通过。
- 状态：已修复，待 E2E selector 回归确认。

### 8. 运动控制配置下拉选项需要组件级交互 selector

- 严重级别：P2
- 现象：`模拟控制器`、`B140 控制器` 被定位到隐藏 `<option>`，不是用户实际点击的 Naive UI 可见下拉面板；`编码器` 在当前状态未出现。
- 用户影响：真实用户可能能操作，但 E2E 无法稳定覆盖控制器类型、位置来源、编码器补偿等配置项。
- 修复：为控制器类型、轴类型、位置来源控件补充稳定 `data-test` 和可访问名称；`UiSelect` 支持向 Naive UI 选择器透传 `aria-label`/`data-test`。
- 验证：`npm run typecheck`、`npm run test`、`npm run build` 通过。
- 状态：已修复，待 E2E selector 回归确认。

## 建议修复顺序

1. 统一前端 API base，消除 `storage`、`traversal`、`motion` 在不同运行模式下的 404/connection refused。
2. 修复运动页浏览器模式状态刷新，避免断开/连接 UI 状态滞后。
3. 修复 toast/modal 遮挡问题，保证弹窗内按钮可稳定点击。
4. 为 Naive UI 复杂控件补稳定 selector 或可访问名称。
5. 补设备管理批量操作和 Wails 独立运动窗口专项 E2E。

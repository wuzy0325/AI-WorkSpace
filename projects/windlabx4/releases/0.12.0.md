# Wind-DAQ v0.12.0

Release date: 2026-07-31
Package: `wind-daq-0.12.0-amd64-installer.exe`

## Summary

本版本修复问题电脑上"退出确认后程序无响应"的卡死问题，并重构 ServiceShutdown
诊断能力。根因：`stopAllMotion` 用 `context.Background()` 无超时，B140 通信
异常时 `queryStatus` 串行多个 sendCommand 累积 ~70s 阻塞，而 ServiceShutdown
在 Wails v3 主线程同步执行，导致 GUI 卡死。

## User-visible Changes

- **退出不再卡死**：问题电脑上 B140 运动控制器通信异常时，退出确认后 GUI 不再
  "无响应"。`stopAllMotion` 改用 3s 有界超时，最坏 3s+5s=8s 内完成退出
  （3s 等 ctx 取消 + 5s 等当前 sendCommand watchdog Close conn）。
- **ServiceShutdown 诊断日志**：每个 shutdown 子步骤（traversal_registry /
  relay_stop / data_stream_relay_stop / terminate_motion_window /
  calibration_mgr_shutdown / api_server_shutdown）记录 step_ms 与 total_ms，
  出问题时可直接从日志定位卡在哪个子步骤，无需复现。

## Fixes

- `stopAllMotion` 用 `context.Background()` 无超时，B140 通信异常时 `StatusAll`
  串行多个 sendCommand 累积 ~70s 阻塞 GUI 主线程（修复：3s 有界超时）。
- `ServiceShutdown` 各子步骤无打点日志，问题电脑卡死时无法定位卡在哪一步
  （修复：抽出 `runShutdownStep` 辅助函数统一打点，失败路径也打点）。
- `stopAllMotion` 注释表述不够精确，未区分未启动命令（立即返回 ctx.Err()）
  与执行中命令（等 watchdog Close conn，最长 5s）的 ctx 取消语义（修复：
  精确化注释）。

## Compatibility

- 配置文件格式：兼容。无新增配置字段，无字段含义变更。
- 数据文件格式：兼容。无变更。
- 设备协议行为：无变化。仅改 `stopAllMotion` 的 ctx 超时，不影响设备通信协议。
- API 契约：兼容。无 backend 方法签名变更，无 frontend bindings 重生成需求。

## Install / Upgrade

- 兼容覆盖安装，无需先卸载旧版本。
- 推荐安装步骤：
  1. 关闭正在运行的旧版本 Wind-DAQ。
  2. 运行 `wind-daq-0.12.0-amd64-installer.exe`，选择安装语言（中文/英文）。
  3. 按向导完成安装，安装程序会自动检测并安装 WebView2 Runtime（如未安装）。
  4. 启动 Wind-DAQ，确认 GUI 正常出现；在连接 B140 运动控制器的电脑上验证
     退出不再卡死。

## Known Issues

- 安装包未进行 Authenticode 数字签名，Windows 可能显示未知发布者提示。
- 该修复针对 B140 运动控制器通信异常场景；若其他设备（T1603 / P1604）通信
  异常时退出仍可能等待单命令 watchdog（5s）超时，但不会累积到 ~70s。

## Rollback

- 可直接卸载 0.12.0 后安装 0.11.4 回退，配置与数据文件无需处理。
- 0.12.0 与 0.11.4 的配置/checkpoint 格式一致，可双向加载。

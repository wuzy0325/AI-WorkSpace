## 1. 当前算法基线

三孔探针由三个孔压计算：

```text
DeltaP = 2*P2 - P1 - P3
Kb = (P3 - P1) / DeltaP
```

运行时可由输入直接观测的校准系数只有 Kb。算法按 Kb 查表得到 `Alpha/K0/Kv`，再恢复：

```text
Pt = P2 + K0*DeltaP
Ps = Pt - Kv*DeltaP
```

多 PRB 文件场景会按当前 Ma 选择距离最近的两个校准档，混合其 Kb/K0/Kv，并迭代恢复 Ma。当前实现不是按排序后的 Ma 选择包围档；三个以上且间距不均匀的 PRB 可能选到位于当前 Ma 同一侧的两个档，随后 ratio 会钳位到 `[0,1]`。

当前约束：

- 各 PRB 的 Alpha 网格必须逐点一致；当前真实 PRB 的 Alpha 还严格递增，但加载器尚未强制该条件；
- 每档 Kb 必须按 Alpha 行序严格递增且无重复；
- Kb 越界时钳位到最近边界点并输出警告；
- 恢复 Ma 超出校准范围时结果无效；
- Go 与小程序 JS 版必须保持算法和数值行为一致。

## 2. 改善项 A：PCHIP 候选插值

### 2.1 目标与限制

当前实现使用分段线性插值。真实 PRB 中 `Kb(Alpha)` 在大角度区域弯曲更明显，PCHIP 可能降低 5° 网格内的截断误差。

PCHIP 不是天然更接近真实气动曲线。它只利用相邻校准节点构造平滑、保形的三次曲线，因此必须先在独立实验数据上证明总体收益，不能仅凭某一组数据改善就替换生产算法。

本项只改变网格内插值。以下行为必须保持：

- Kb 越界仍钳位，不做线性或三次外推；
- Ma 档混合和迭代流程不变；
- 无效输入、非物理气动状态及 Ma 超范围判定不变；
- 不新增公开 API 字段，不改变 PRB 文件格式。

### 2.2 明确的 PCHIP 数学规范

采用非均匀横坐标版本的 PCHIP。对严格递增节点 `(x_i, y_i)` 定义：

```text
h_i = x_(i+1) - x_i
d_i = (y_(i+1) - y_i) / h_i
```

内部节点导数使用加权调和均值：

```text
若 d_(i-1) == 0、d_i == 0 或二者异号：m_i = 0
否则：
  w1 = 2*h_i + h_(i-1)
  w2 = h_i + 2*h_(i-1)
  m_i = (w1 + w2) / (w1/d_(i-1) + w2/d_i)
```

首端点导数：

```text
m_0 = ((2*h_0 + h_1)*d_0 - h_0*d_1) / (h_0 + h_1)
```

末端点使用对称公式。端点导数必须经过保形限幅：

```text
若 sign(m_0) != sign(d_0)：m_0 = 0
否则若 sign(d_0) != sign(d_1) 且 abs(m_0) > abs(3*d_0)：m_0 = 3*d_0
```

末端点同理。若只有两个节点，两个端点导数均取唯一割线斜率。

在区间 `[x_i, x_(i+1)]` 内：

```text
t = (x - x_i) / h_i
y = (2*t^3 - 3*t^2 + 1)*y_i
  + (t^3 - 2*t^2 + t)*h_i*m_i
  + (-2*t^3 + 3*t^2)*y_(i+1)
  + (t^3 - t^2)*h_i*m_(i+1)
```

此规范保证对单调节点数据进行保形插值，不应表述为保证数学意义上的“严格单调”。Go 与 JS 必须使用相同公式、比较条件和端点规则。

### 2.3 两个独立候选

本项必须分别评估，不预设“所有输出采用同一种插值器”才正确：

- **A1，仅 Alpha PCHIP**：`Alpha(Kb)` 使用 PCHIP，K0/Kv 保持线性插值。该方案隔离角度插值收益，不改变气动系数的插值方法；
- **A2，全部系数 PCHIP**：`Alpha(Kb)`、`K0(Kb)`、`Kv(Kb)` 均使用 PCHIP。该方案额外改变 Pt/Ps/Ma，必须独立证明收益。

三个因变量可以使用不同插值器，不存在必须统一的数学要求。A2 不能借用 A1 的角度改善结果作为启用依据。

### 2.4 单文件实现

单文件加载时，以 Kb 为横坐标。A1 只为 Alpha 预计算导数；A2 分别为三个因变量预计算导数：

```text
Alpha(Kb)
K0(Kb)
Kv(Kb)
```

运行时通过二分查找定位 Kb 区间，再按所选候选方案求值。

### 2.5 多文件实现

多文件路径不能复用任一原始 Ma 档预计算的导数，因为当前 Ma 每次迭代都会改变混合后的 Kb 横坐标和 K0/Kv 值。

每次按现有“最近两个档”策略确定 Ma 混合比例后，应按以下顺序处理：

1. 按共同 Alpha 下标混合选中的两个 Ma 档的 Kb/K0/Kv；
2. 确认混合后的 Kb 仍严格递增；
3. A1 只构造 Alpha 的 PCHIP 导数，K0/Kv 沿用线性插值；A2 分别构造 Alpha、K0、Kv 的 PCHIP 导数；
4. 用同一个 `kbMeasured` 按候选方案求值。

步骤 2 理论上由两个严格递增序列的凸组合保证，但仍应保留测试，防止后续 Ma 外推或数据策略变化破坏前提。PCHIP 与跨 Ma 混合在代码步骤上可分离，在数值上并非互不影响。

### 2.6 Alpha 单调前提

`Alpha(Kb)` 要保持单调，除 Kb 严格递增外，Alpha 节点也必须严格递增。当前真实 PRB 满足该条件，但现有加载器只检查各档 Alpha 网格一致，尚未检查 Alpha 本身单调。

启用 A1 或 A2 前，加载器必须增加 Alpha 严格递增校验；不满足时拒绝加载并返回包含文件名和相邻节点的明确错误。K0/Kv 不要求单调，不能宣称其 PCHIP 输出整体单调。

### 2.7 现有实验结果的定位

以下是早期探索记录，尚未在仓库中固化生成脚本，也未明确对应 A1 还是 A2，**当前不可复现，不作为启用证据**：

| 数据 | 分段线性 RMS | PCHIP RMS | 变化 |
|---|---:|---:|---:|
| 0.1Ma | 0.1539° | 0.1616° | +5.0% |
| 0.3Ma | 约 0.3605° | 0.2938° | 约 -18.5% |
| 0.5Ma | 1.1943° | 1.1820° | -1.0% |

其中 0.3Ma 线性值以现有精度报告的 `0.3605°` 为准；PCHIP 值和算法变体尚无可追溯产物。该记录最多说明 PCHIP 值得继续验证，不能证明它已优于线性插值：0.1Ma 有退化，且三组数据均参与了方案选择，不属于独立验证集。固化脚本后应删除本手工表，改为链接机器生成报告。

### 2.8 启用门槛

只有同时满足以下条件，才能把 PCHIP 设为生产默认：

- 固化可重复运行的对比脚本、输入数据、角度真值来源和输出报告，并明确区分 A1/A2；
- 至少增加一组未参与算法选择的独立实验数据；
- 按 Ma、正负角、中心段和大角度段分别报告 Bias、RMS、P95 和最大绝对误差；
- 独立验证集总体 RMS 优于线性基线；
- 任一有效 Ma/角度分组的 RMS 退化不超过预先约定阈值；建议初始阈值为 2%，最终由算法负责人确认；
- Go 与 JS 固定向量的离散字段精确一致，浮点字段满足预先固定的绝对或相对容差；
- 性能基准证明多文件迭代内重建导数不会造成不可接受的回归。

若未达到门槛，保留分段线性，不以调参方式针对现有验证集继续优化。

## 3. 改善项 B：K0/Kv 校准质量检查

### 3.1 否决的原方案

不实施“K0/Kv 联合反算 Alpha”或“K0 独立反算 Alpha”。原因如下：

- 运行时没有独立的 Pt/Ps 观测，无法从 P1/P2/P3 计算实测 K0/Kv；
- K0/Kv 是算法根据 Kb 定位后用于恢复 Pt/Ps 的表值，不是额外的独立测量信息；
- 真实 PRB 中 K0/Kv 关于 Alpha 通常呈 U 型，同一个值可能对应正负两个角度，不能唯一反演 Alpha；
- 将由 Kb 选出的 K0/Kv 再用于校验同一个 Kb 解属于循环论证，不能提供独立自检能力。

只有未来输入增加独立总压或静压参考测量时，才可重新评估 K0/Kv 残差校验。

### 3.2 可实施的替代方案

K0/Kv 仅用于加载期校准质量检查：

- 所有值必须有限；该项现有解析器已覆盖；
- 检查相邻点突跳，可输出带文件名和 Alpha 的诊断；
- 检查正负角对称性偏差，但仅作为报告，不默认拒绝加载；
- 检查跨 Ma 档同一 Alpha 的系数突变，但阈值必须来自历史合格 PRB 的统计分布；
- 不假设 K0/Kv 单调，不以 U 型或局部波动直接判文件非法。

在没有合格样本分布和阈值依据前，本项只保留为研究任务，不加入生产加载器。

## 4. 改善项 C：低 DeltaP 置信度标记

### 4.1 目标

现有 `abs(DeltaP) < 1e-6` 直接判无效。高于该阈值但接近传感器噪声量级时，Kb 和 Alpha 可能仍非常不稳定，需要向用户提示低置信度。

### 4.2 推荐方法

优先基于压力测量不确定度，而不是使用无来源的固定 Pa 阈值。保持 `InterpolationInput` 公开字段不变，由插值器构造配置注入三个通道的不确定度和协方差模型；若上层没有该配置，则不启用不确定度警告。

给定协方差模型后，对

```text
Kb = (P3-P1) / (2*P2-P1-P3)
```

按一阶误差传播计算 `sigmaKb`，再用当前插值曲线的局部斜率估计：

```text
sigmaAlpha ~= abs(dAlpha/dKb) * sigmaKb
```

误差传播必须明确三个通道是否独立、是否同方差，以及零点补偿造成的相关误差，不能用未定义的单一 `sigmaP` 代替协方差模型。当 `sigmaAlpha` 超过产品定义的角度容差时，保留结果并附加低置信度 Warning。

### 4.3 分阶段落地

若第一版无法获得传感器噪声参数，可以采用实测固定阈值，但必须先记录：

- 输入压力单位为 Pa；
- 适用的传感器型号、量程、精度和采样平均策略；
- 阈值对应的实验数据和误判/漏判结果；
- 阈值是否适用于所有设备，还是由上层配置；
- Warning 与 `IsValid` 的产品语义。

阈值未确定前不提交占位常量。默认建议“保留结果 + Warning”，不改变 `IsValid`；若产品决定低置信度即无效，则属于公开行为变化，需单独评审。

## 5. 改善项 D：越界外推

不实施。Kb 超出校准范围通常意味着探针超出有效工作角。继续使用最近边界点钳位，并保留越界警告。

现有 Warning 文案中的“外推”容易误解，后续可单独改为“已钳位到最近校准边界”。该文案调整不应与数值算法改动混在同一提交中。

## 6. 改善项 E：移除多文件运行时排序

### 6.1 前提

已实施的加载器一致性校验见 `three-hole-interpolation-improvements.md` §A4：

- 各 Ma 档 Alpha 网格逐点一致；
- 每档 Kb 按 Alpha 行序严格递增。

对任意 `ratio` 位于 `[0,1]` 的两个严格递增 Kb 序列，逐点凸组合后仍严格递增。因此 `interpolateWithWarning` 构建 entries 后不需要再次执行 `sort.Slice`，可以按原 Alpha 下标顺序直接二分定位。

### 6.2 实施边界

- 仅删除 entries 的运行时排序并改为二分查找；
- 不改变“最近两个 Ma 档”的选择、ratio 计算、钳位或 Warning；
- 若未来允许 Ma 外推使 ratio 超出 `[0,1]`，必须重新验证单调性，不能沿用当前证明；
- 二分必须复现当前线性扫描的区间语义：选择第一个满足 `entries[j+1].Kb >= kbMeasured` 的左区间；内部节点仍执行原插值表达式，避免改变浮点运算路径；
- 保持相同运算路径时，实施前后的结果应逐位比较；若实现选择直接返回节点，则改用评审前固定的逐字段绝对/相对容差并记录差异，不能只重生成 golden。

## 8. 验收标准

### 8.1 A：PCHIP 候选算法

- [ ] 非均匀节点、端点、两节点退化规则与 §2.2 完全一致；
- [ ] 在每个网格节点精确过点，浮点容差明确；
- [ ] 加载器拒绝非严格递增的 Alpha 网格；
- [ ] 对严格单调 Alpha 节点，插值结果不产生反向区间或过冲；
- [ ] Kb 越界行为和警告语义不变；
- [ ] A1/A2 分别覆盖单文件和多文件路径，报告各自的 Alpha/K0/Kv/Pt/Ps/Ma；
- [ ] 当前两档数据的 Ma 档边界附近 Alpha/Pt/Ps/Ma 连续；三个以上 Ma 档的选择连续性属于现有“最近两个档”策略的独立问题，不归入 PCHIP 验收；
- [ ] 独立实验数据满足 §2.8 启用门槛；
- [ ] Go/JS 离散字段和 Warning 精确一致；Alpha/Pt/Ps/Ma/Velocity 使用预先固定的绝对或相对容差，禁止测试通过后放宽；
- [ ] 所有输出为有限值，现有无效输入与气动校验回归通过。

### 8.2 B：K0/Kv 质量检查

- [ ] 有限性和格式等确定性规则不依赖统计阈值；
- [ ] 突跳、对称性和跨 Ma 变化等统计规则都有历史合格 PRB 的分布与预先固定阈值；
- [ ] 统计诊断包含文件名、Alpha、实际值和阈值；
- [ ] 对称性和突跳规则默认只警告，不因真实 U 型曲线误拒绝；
- [ ] 不从 K0/Kv 独立反算 Alpha；
- [ ] 不使用由同一 Kb 解出的 K0/Kv 做循环交叉校验。

### 8.3 C：低 DeltaP 置信度

- [ ] `abs(DeltaP) < 1e-6` 的无效行为保持；
- [ ] 阈值或不确定度模型有传感器参数与实测数据支撑；
- [ ] 边界等于阈值时的行为明确；
- [ ] Warning 与 IsValid 语义经产品确认；
- [ ] 覆盖不同 DeltaP、正负角和不同局部 `dAlpha/dKb` 的测试。

### 8.4 E：移除排序

- [ ] 用属性测试证明 `[0,1]` 凸组合保持严格递增；
- [ ] 二分区间边界语义与现有线性扫描一致；
- [ ] 保持相同浮点运算路径时，多文件结果逐位一致；否则使用评审前固定的逐字段容差；
- [ ] 基准测试记录耗时和分配变化；
- [ ] Go、桌面后端和小程序相关测试全部通过。

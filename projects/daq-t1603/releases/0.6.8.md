# DAQ-T-1603 v0.6.8

Release date: 2026-08-04
Package: daq-t1603-0.6.8-amd64-installer.exe

## Summary

修复设备连接同步时"设备端持久化通道掩码覆盖应用配置"的缺陷：此前启动采集实际发送 `@f0 0000 2`（零通道），导致无数据帧且停止采集报 `invalid Stop response boundary: bytes=5 expected N*68+ACK; raw=22 00 00 00 41`。现恢复为应用配置的 `@f0 FFFF 2`（全通道启用）。

## User-visible Changes

- 连接设备后启动采集，实际发送的启动命令恢复为 `@f0 FFFF 2`（全 16 通道启用），数据帧恢复为 `N×68 + ACK` 结构，停止采集不再报边界错误。

## Fixes

- **设备端 MCH 覆盖应用通道掩码**：连接同步阶段 `readAllConfig` 会执行 `@fd MCH` 读取设备内部持久化的通道掩码（设备出厂/历史遗留值为 `0000`），此前无条件写回 `cfg.ChannelMask`，把 profile 配置的 `FFFF` 覆盖成 `0000`；随后 `StartAcquisition` 用 `d.config.ChannelMask` 拼出 `@f0 0000 2`。设备以零通道掩码启动采集时（HEAD=1 帧序列模式）不输出通道数据，数据流只有 4 字节序列头帧，Stop 尾部变为 4 字节 + ACK `'A'`，不满足 `N×68+ACK` 边界校验，报 `invalid Stop response boundary: bytes=5 expected N*68+ACK; raw=22 00 00 00 41`。修复：`@fd MCH` 仍被读取以维持协议响应边界与后续命令时序，但不再覆盖 `cfg.ChannelMask`；mask 为空时的默认回退逻辑（`FFFF`）保持不变。

## Compatibility

- 配置文件格式兼容（`ChannelMask` 字段语义不变，仍是应用侧权威配置）。
- CSV 数据格式不变。
- 设备协议命令链不变（`@fd MCH` 仍会读取，仅不再回写应用配置）。
- 扫描协议（UDP 广播 + 单播响应）不变。

- 运行 `daq-t1603-0.6.8-amd64-installer.exe`，安装后启动应用确认主窗口正常出现。

# DAQ-T-1603 v0.6.5

Release date: 2026-07-31
Package: daq-t1603-0.6.5-amd64-installer.exe

## Summary

修复 ADR-009 故障 Windows 机器（安全软件 LSP hook winsock 导致 `SetReadDeadline` 失效）上 Stop 采集卡死的问题：Stop 静默确认窗口（150ms）依赖 deadline 唤醒，失效机器上该 Read 永久阻塞，Stop 只能掉到 350ms 兜底废弃连接。本次通过连接建立后的自动探测将故障机器切到 goroutine + 真定时器窗口，Stop 在 150ms 静默确认后正常完成（约 151ms），不再依赖失效的 deadline；同时保留并梳理了连接回收语义（故障机器每轮 Stop 后自动重连，正常机器连接复用零影响）。

## User-visible Changes

- 故障 Windows 机器上 Stop 采集从 350ms 兜底提速至约 151ms 正常完成，不再卡死（裸 TCP 探针 + 实机 2 轮 sdkstopprobe 验证）。
- 故障机器每轮 Stop 后自动回收连接并重连（遗留读 goroutine 使连接不可复用），UI 无报错、无断连噪音；正常机器行为不变（Stop 后连接复用，无重连）。

## Fixes

- **Stop 静默窗口 deadline 失效修复**（`shared/device-sdk/go/protocol/daq_t1603_frame.go`）：`readFrameFixed` 的 collectingStop 分支按 `deadlineBroken` 分两路——正常机器保持同步 `SetReadDeadline` 窗口（无遗留 goroutine，连接可复用）；故障机器用固定 150ms goroutine 阻塞读 + 定时器窗口，窗口内数据到达即收集（goroutine 无残留），窗口到期非阻塞收取竞争数据后仍无数据则挂 `stopTailCh` 归队并标记 `dirty`（连接不可复用），按 buffer 验证 `N×frameSize+ACK` 边界：合法 → 完成收集；有内容但非法 → 协议错位报错；空 → 上层 350ms 兜底。新增 `stopTailCh`/`drainStopTail`（遗留读结果归队，避免抢走后续事务数据）、`SetDeadlineBroken`/`IsDirty`，恢复 `isTimeoutError`。
- **设备层 deadline 探测与连接收尾**（`shared/device-sdk/go/daq/hardware/daq_t1603.go`）：`connectLocked` 连接建立后空窗期 `probeDeadlineBroken(conn)`（20ms deadline + goroutine 读 + 30ms 判定，结果 device 级缓存，只探一次）；探测失效则后台 `protocol.AbortConnection`（CloseWrite FIN 解除探测读 + Close）+ `WatchdogClose` 500ms 兜底收尾旧连接并重连一次（直接 `conn.Close()` 在挂起 Read 的故障机器上会永久阻塞）；`StopAcquisition` 完成分支对 `IsDirty()` 连接走废弃路径（Stop 仍返回 nil，下次 Start 自动重连），日志统一为 `Stop completed; connection closed by Stop owner (not reusable)`。
- **测试**（`shared/device-sdk/go/daq/hardware/daq_t1603_test.go`）：`TestDAQT1603StopWithACKOnDeadlineFailingConn` 重写为单轮、模拟 `deadlineBroken=true`、期待 Stop 正常完成且连接回收、`onReadLoopExit` 零触发；删除问题机器上不可达的"分段尾帧复用连接"场景测试（finalize 成功时窗口内 goroutine 必然仍阻塞，连接必然不可复用）。

## Known Issues

- ADR-009 故障机器（deadline 失效）上 Stop 后连接必然回收并重连（遗留读 goroutine 无法唤醒），属预期行为；如设备固件可改，可引入"Stop 回复带头帧计数"协议彻底消除静默窗口（见会话记录方案）。
- SDK go.sum 的 x/sys 校验和损坏，SDK 全量 `./...` 测试不可用（仅影响开发环境，不影响打包）。

## Rollback

- 可直接卸载 0.6.5 并重新安装 0.6.4，配置和数据文件无需处理。
- 0.6.4 在正常机器上可正常工作；故障机器回退后 Stop 恢复 350ms 兜底（可用但较慢）。

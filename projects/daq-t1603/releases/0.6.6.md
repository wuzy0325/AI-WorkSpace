# DAQ-T-1603 v0.6.6

Release date: 2026-07-31
Package: daq-t1603-0.6.6-amd64-installer.exe

## Summary

紧急修复 0.6.5 引入的两个现场故障：(1) deadline 探测失效后重连的**设备槽位竞态**——旧连接 FIN 尚未被设备处理时立即重连，新连接被设备拒绝（配置同步 EOF）；(2) 连接毒化路径的 **`conn.Close()` 永久阻塞**——问题电脑挂起 Read 时 Close 卡死（closesocket 等待未完成重叠读取），连接永不关闭、设备单连接槽位泄漏，之后所有连接被设备拒绝（EOF）。两者叠加导致 0.6.5 实机出现 Stop 3s 超时失败 + 设备失联（后续连接全部 EOF，需杀进程/重启设备恢复）。

## User-visible Changes

- 0.6.6 在 ADR-009 故障机器上 4 轮 Start/Stop 实机验证全部 151ms 正常完成（branch=done 正常路径），无 3s 超时、无连接失败。
- 修复设备失联问题：毒化连接不再卡死，设备单连接槽位正常释放，后续连接不再被设备拒绝。

## Fixes

- **probe 重连竞态修复**（`shared/device-sdk/go/daq/hardware/daq_t1603.go` `connectLocked`）：`probeDeadlineBroken` 判定失效后，后台 `AbortConnection`（CloseWrite FIN + Close）与递归 `connectLocked` 并发——设备仅允许单连接，旧连接 FIN 传播 + 槽位释放需要时间，立即重连被设备拒绝（`@e3` 读取 EOF，2026-07-31 实机复现）。修复：递归重连前 `time.Sleep(200ms)` 等待设备处理 FIN（仅此一次，`deadlineProbed` 已置位）。CloseWrite(FIN) 在 AbortConnection 内同步首步执行，此刻已发出。
- **连接毒化 Close 阻塞修复**（三处）：`invalidateConnection`、`invalidateConnectionAfterReadLoopTimeout`、readLoop no-data timer 回调、`connectLocked` 配置同步失败路径的原 `conn.Close()` 在问题电脑挂起 Read 时永久阻塞（closesocket 等待未完成重叠读取）→ 连接永不关闭 → **设备单连接槽位泄漏 → 后续所有连接被设备拒绝（EOF）**（2026-07-31 实机复现：应用进程 ESTABLISHED 连接占着设备 9000 端口 30+ 分钟，杀进程后恢复）。全部改为后台 `go protocol.AbortConnection(conn)` + `WatchdogClose(conn, 500ms)` 兜底（与 probe 收尾/Stop 兜底一致）。
- **Stop 路径诊断日志**：`stopAcquisitionLocked` select 三分支（done/quietFallback/3s timeout）、quiet timer 触发、collectingStop 窗口路径（sync/goroutine）均打 debug 日志；`probeDeadlineBroken` 结果打 info/warn 日志（`Read deadline works/broken on this machine`），便于现场定位 Stop 卡点。

## Install / Upgrade

- 兼容覆盖安装，**无需卸载旧版本**。
- 若当前设备无法连接（0.6.5 遗留槽位泄漏）：先退出所有 DAQ-T-1603 进程（或重启设备），再安装 0.6.6。
- 推荐的安装步骤:
  1. 关闭正在运行的旧版本 DAQ-T-1603（任务管理器确认无 daq-t1603 进程残留）。
  2. 双击 `daq-t1603-0.6.6-amd64-installer.exe` 进行覆盖安装。
  3. 启动新版本，连接设备验证连续启停采集(Start→Stop) ≥ 30 轮无错误。
- 如需卸载旧版本残留:通过"控制面板 → 卸载"或安装目录下的 `Uninstall.exe` 完成。

# 1604Cal Domain Context

1604Cal 是一个面向压力计量与标定流程的桌面系统，核心关注设备连接、压力控制、计量采集、标定采集与报告生成之间的业务边界。

## Language

**单活工作流**:
系统同一时刻只允许一个业务流程拥有设备操作上下文。
_Avoid_: 多租约并发, 模块并行绑定

**工作流冲突**:
新的业务流程试图绑定或操作设备时，已有业务流程仍处于活跃状态。
_Avoid_: 自动抢占, 静默切换

**活跃工作流**:
已经进入准备、暂停、打压、稳定、采集、报警处理、待人工采集、测点完成或拟合阶段的业务流程。
_Avoid_: 已完成流程, 错误流程, 单纯设备连接

**安全释放**:
工作流结束或出错时停止打压、停止采集并释放设备操作上下文。
_Avoid_: 仅清 token, 静默忽略硬件状态

**需要人工处理**:
系统无法确认设备已安全释放，必须由操作者检查硬件后才能继续新流程。
_Avoid_: 普通错误, 自动恢复中

**工作流所有者**:
拥有或请求设备操作上下文的业务入口，在值上限定为计量工作流或标定工作流。
_Avoid_: moduleName, 页面名称

**设备维护操作**:
设备管理或多打压控制发起的连接、断开、读取、复位、切阀、改单位、注册、注销、设压、停止、排空等非业务流程操作。
_Avoid_: 业务工作流, 工作流所有者

**设备操作上下文**:
一次业务流程执行期间可操作的计量设备、打压设备与相关控制权限。
_Avoid_: 全局 session token, 页面状态

## Relationships

- 一个 **单活工作流** 拥有一个 **设备操作上下文**
- 一个 **设备操作上下文** 可包含一个计量设备和零个或一个打压设备
- 一个 **设备操作上下文** 必须属于一个 **工作流所有者**
- 每次业务流程启动都会形成新的 **设备操作上下文**；旧流程的延迟请求不得操作新流程的设备上下文
- 活跃期间同一 **工作流所有者** 对同一设备组合的重复绑定是幂等操作；尝试更换设备组合应视为 **工作流冲突**
- 新的 **单活工作流** 启动前必须确认不存在 **工作流冲突**
- 发生 **工作流冲突** 时，后端拒绝新的绑定或操作请求，前端提示用户先停止当前流程
- **工作流冲突** 必须由后端统一判定和拒绝；前端禁用按钮只能作为交互提示，不能作为唯一保护
- 状态迁移应通过统一的工作流协调入口执行，避免计量或标定服务绕过 **工作流冲突**、**安全释放** 和 **需要人工处理** 规则
- 系统保留一个底层会话状态机；计量和标定只能通过各自的业务动作触发状态变化，不直接暴露任意状态迁移
- **工作流所有者** 仅包含计量工作流和标定工作流；设备维护不属于工作流所有者
- 活跃工作流期间 **设备维护操作** 允许读取所有设备状态，不允许对任何设备执行写操作
- 紧急停止全部设备始终允许执行，是维护写操作的唯一例外；执行后当前工作流进入 **需要人工处理**
- `ready`、`paused`、`pressurizing`、`stabilizing`、`collecting`、`await_alarm_resolution`、`await_manual_collect`、`point_done`、`fitting` 表示 **活跃工作流**
- `idle`、`stopped`、`completed`、`error` 不表示 **活跃工作流**
- `completed` 不占用 **设备操作上下文**，但保留压力点、采集数据、拟合结果和报告所需信息
- 工作流进入 `error` 时必须先执行 **安全释放**；释放成功后允许新流程，释放失败时应阻止新流程并提示人工处理
- **安全释放** 失败时，流程进入 **需要人工处理** 状态，并阻止新的业务流程绑定或启动
- 处于 **需要人工处理** 状态时，操作者可执行"确认已人工处理"；系统重新读取设备连接、单位、阀门和压力状态，成功后回到 `idle` 并释放设备操作上下文
- 停止计量或标定流程时应执行 **安全释放**，但不自动断开设备连接；设备连接属于可复用准备资源
- 报告导出依赖最近一次完成的流程结果，不依赖活跃设备操作上下文

## Example dialogue

> **Dev:** "计量采集正在运行时，用户能否在标定页重新绑定另一套设备？"
> **Domain expert:** "不能并行工作；系统是单活工作流，新的绑定必须先停止或释放当前工作流。"

> **Dev:** "采集过程中设备通信断了，进入 error 状态——用户可以做什么？"
> **Domain expert:** "系统会自动停止打压和采集尝试释放硬件。如果释放成功，新流程可以开始；如果释放失败，状态变为"需要人工处理"，用户必须检查设备并点击确认后才能继续。"

> **Dev:** "每次停止流程都要断开设备连接吗？"
> **Domain expert:** "不需要。停止采集和打压就可以了，设备连接保留着下一个流程直接复用。只有用户主动点"断开"才关闭连接。"

> **Dev:** "多打压页能在采集运行时调整目标压力吗？"
> **Domain expert:** "不可以。活跃工作流期间多打压只能看压力值，不能设压、排空或停止——除非真的紧急，紧急停止会中断当前采集流程并标记为需要人工处理。"

## Flagged ambiguities

- "设备会话租约"曾被理解为多模块各自持有 token；已解析为 **单活工作流** 下的 **设备操作上下文**。
- "切换模块"不表示自动抢占设备；已解析为发生 **工作流冲突** 时必须显式停止当前流程。
- "状态迁移失败"不等同于 **工作流冲突** 或 **需要人工处理**；后两者需要可被前端明确识别的后端错误契约。
- "维护操作"和"多打压控制"有重叠；已合并为 **设备维护操作**。

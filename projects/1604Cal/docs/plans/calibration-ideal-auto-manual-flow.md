# 标定模块理想流程（自动 / 手动）探索稿

> 文档日期：2026-04-21
> 文档性质：探索与方案沉淀（非实现说明）
> 适用范围：Cal1604 标定模块

---

## 1. 目标与边界

本文件用于沉淀标定模块的**理想业务流程**，分为自动模式与手动模式两条主线。

目标：

- 统一工程、前端、后端、设备对流程语义的理解。
- 为后续接口对齐、状态机收敛、联调验证提供基准。
- 与当前实现解耦，先定义“应该怎样工作”。

非目标：

- 不描述具体代码实现。
- 不约束页面视觉样式。

### 1.1 已确认业务口径（依据当前页面与用户反馈）

1. **阀门切换是人工行为**：通过设备卡片中的阀门控制完成。
2. **开始校准前必须满足阀门前提**：计量设备阀门状态必须为 `calibration`。
3. **测点数可配置范围固定**：最小 2 点，最大 6 点。

---

## 2. 参与角色（四泳道）

- **校准工程师**：执行连接、启动、确认、重试、结束等业务操作。
- **前端（Vue/Store）**：承载交互状态、调用 API、展示反馈。
- **后端（API + 应用服务 + 状态机）**：执行业务规则、流程编排、事件发布。
- **设备（1604 + 打压设备）**：执行阀门切换、控压、采集、拟合写入等硬件动作。

### 2.1 画面结构约束（依据现场操作画面）

- 页面采用双表结构：
  - 上方：**压力点设置表**（用于逐点操作）
  - 下方：**采集数据表**（用于结果展示）
- 压力点设置表应包含固定列：`序号 / 状态 / 目标压力 / 确认 / 采集 / 操作`。
- 每个测点的“确认、采集、删除/重采”等操作按钮，必须位于上方压力点设置表对应行。
- 下方采集数据表以展示为主（压力点、目标压力、CH1~CHn、状态、导出），不承担逐点确认/采集主操作。

## 3. 理想自动流程（Auto）

### 3.1 前置条件

1. 1604 设备已连接且可读写。
2. 1604 阀门由工程师在设备卡片中手动切换到 `calibration`。
3. 打压设备已连接且可控压。
4. 压力单位一致（不一致需阻断或明确确认）。
5. 通道已选择（>= 1），默认是全部选择。
6. 标定参数有效（测点数 2~6、量程、采样数、稳定时间）。

### 3.2 四泳道流程图

```text
┌──────────────┬──────────────────────────┬────────────────────────────────┬────────────────────────────┐
│ 校准工程师   │ 前端（Vue/Store）        │ 后端（API/Service/StateMachine）│ 设备（1604 + 打压）        │
├──────────────┼──────────────────────────┼────────────────────────────────┼────────────────────────────┤
│ 手动切阀门    │ 设备卡片发起阀门控制请求    │ 执行阀门切换并回读阀门状态       │ 1604 切换到 calibration     │
│ (前置动作)    │ 展示“已校准状态”           │ 记录可启动条件满足               │ -                          │
├──────────────┼──────────────────────────┼────────────────────────────────┼────────────────────────────┤
│ 配置参数并开始│ 提交配置与启动请求        │ 校验前置条件（含阀门=calibration）│ -                         │
│              │                          │ 状态 idle->ready->pressurizing │ -                          │
├──────────────┼──────────────────────────┼────────────────────────────────┼────────────────────────────┤
│ 观察进度      │ 订阅事件并更新进度         │ 进入自动循环（for each point）   │ -                          │
│              │                          │ 1) 打压                         │ 打压设备控压到目标压力       │
│              │                          │ 2) 稳定等待                     │ 反馈稳定状态                 │
│              │                          │ 3) 采集                         │ 1604 执行多次采样            │
│              │                          │ 4) 单点完成 point_done          │ -                          │
├──────────────┼──────────────────────────┼────────────────────────────────┼────────────────────────────┤
│ 报警时决策    │ 弹窗提示 continue/retry   │ 偏差超阈值 -> await_alarm_resolution │ -                    │
│              │ 发送用户决策              │ continue: 下一点；retry: 重采当前点 │ 重试时再次打压/采集       │
├──────────────┼──────────────────────────┼────────────────────────────────┼────────────────────────────┤
│ 所有点完成后拟合│ 展示拟合进度与结果         │ 状态 -> fitting -> completed    │ 1604 拟合并保存系数         │
├──────────────┼──────────────────────────┼────────────────────────────────┼────────────────────────────┤
│ 点击结束      │ 提交 stop/end 请求         │ 结束流程并清理资源              │ 停压；阀门待人工切回 measurement │
│              │ 重置本地流程态             │ 发布完成/停止事件               │ -                          │
└──────────────┴──────────────────────────┴────────────────────────────────┴────────────────────────────┘
```

### 3.3 关键状态迁移（理想）

```text
idle -> ready -> pressurizing -> stabilizing -> collecting -> point_done
point_done -> pressurizing (下一点) | fitting
collecting -> await_alarm_resolution -> collecting | point_done
fitting -> completed
任意运行态 -> paused -> pressurizing
任意运行态 -> stopped
```

### 3.4 自动模式关键规则

- 开始前必须通过设备卡片人工切阀到 `calibration`，后端负责校验，不代替人工切换。
- 单点循环由后端统一编排，前端不逐点下发打压/采集命令。
- 报警决策必须显式（continue/retry），禁止静默跳过。
- 完成态之前必须完成拟合（除非流程被停止）。
- 结束时必须执行资源回收：停压、停止后台循环；阀门回测量由设备卡片人工执行。

## 4. 理想手动流程（Manual）

### 4.1 前置条件

1. 1604 设备已连接。
2. 1604 阀门由工程师在设备卡片中手动切换到 `calibration`。
3. 打压设备可选：
   - 已连接：可用“系统打压 + 人工确认”。
   - 未连接：人工外部压力源打压。
4. 通道与参数配置有效（测点数 2~6）。

### 4.2 四泳道流程图

```text
┌──────────────┬──────────────────────────┬────────────────────────────────┬────────────────────────────┐
│ 校准工程师   │ 前端（Vue/Store）        │ 后端（API/Service/StateMachine）│ 设备（1604 + 打压）        │
├──────────────┼──────────────────────────┼────────────────────────────────┼────────────────────────────┤
│ 手动切阀门    │ 设备卡片发起阀门控制请求    │ 执行阀门切换并回读阀门状态       │ 1604 切换到 calibration     │
│ (前置动作)    │ 展示“已校准状态”           │ 记录可启动条件满足               │ -                          │
├──────────────┼──────────────────────────┼────────────────────────────────┼────────────────────────────┤
│ 配置并开始    │ 提交配置与启动            │ 校验前置条件（含阀门=calibration）│ -                         │
│              │                          │ 状态 idle->ready                │ -                          │
│              │                          │ 进入待手动采集流程态            │ -                          │
├──────────────┼──────────────────────────┼────────────────────────────────┼────────────────────────────┤
│ 对当前点施压  │ 点击“打压”或仅确认外部施压 │ /pressurize（有打压设备时）      │ 打压设备控压或人工外部施压   │
│ 确认已稳定    │ 点击“确认压力”            │ 状态进入 await_manual_collect   │ 返回稳定或由人工确认         │
├──────────────┼──────────────────────────┼────────────────────────────────┼────────────────────────────┤
│ 点击“采集”    │ 发送 /collect(point)      │ 执行采样并平均，状态 collecting->point_done │ 1604 采样            │
│ 需要时重采    │ 点击“重新采集”            │ 重置当前点并重采                │ 重复当前点采样              │
├──────────────┼──────────────────────────┼────────────────────────────────┼────────────────────────────┤
│ 切换下一点    │ 更新表格当前行             │ point_done -> (下一点)           │ -                          │
│              │                          │ 全部完成后进入可拟合态          │ -                          │
├──────────────┼──────────────────────────┼────────────────────────────────┼────────────────────────────┤
│ 点击拟合/结束 │ 提交 /fit 与 stop/end      │ fitting -> completed             │ 1604 拟合写系数，流程收尾    │
└──────────────┴──────────────────────────┴────────────────────────────────┴────────────────────────────┘
```

### 4.3 手动模式关键规则

- 开始前阀门必须由人工在设备卡片切到 `calibration`。
- 节奏控制权在工程师：逐点推进，逐点确认。
- 前端必须清晰提示当前点的可操作动作（打压/确认/采集/重采），并固定在上方压力点设置表的行操作位。
- 手动模式仍需遵守完整结束条件：拟合成功后再结束，或显式停止并记录中断原因。

## 5. 自动与手动差异矩阵（理想）

| 维度 | 自动模式 | 手动模式 |
|---|---|---|
| 阀门切换 | 人工在设备卡片切换，系统只校验 | 人工在设备卡片切换，系统只校验 |
| 节奏控制 | 后端流程编排 | 工程师逐步触发 |
| 单点推进 | 自动循环 | 人工逐点确认 |
| 打压方式 | 系统自动控压 | 自动控压或人工外部施压 |
| 稳定判定 | 设备稳定信号 + 稳定时间 | 人工确认为主，可辅以稳定信号 |
| 报警处理 | 强制 continue/retry 决策 | 可按点重采，报警可人工处置 |
| UI 重点 | 进度可视化与异常提示 | 上方点位表行操作 + 下方数据表结果展示 |
| 测点数约束 | 2~6 | 2~6 |

---

## 6. 统一收尾与异常原则

### 6.1 收尾原则

- 无论自动/手动，结束时必须执行：
  - 停止打压控制。
  - 停止后台采集循环（若存在）。
  - 由工程师通过设备卡片将阀门切回 `measurement`。
  - 发布最终状态事件（completed 或 stopped）。

### 6.2 异常原则

- 设备断连：立即中止危险动作（控压/采集），保留已采数据。
- 状态非法迁移：拒绝请求并返回明确错误。
- 采集超时：标记当前点错误，允许 retry。

---

## 7. 验收检查清单（流程层）

1. 自动模式能否在“开始后”无需逐点点击完成整轮采集。
2. 阀门未处于 `calibration` 时是否阻断开始校准。
3. 测点数是否严格限制在 2~6（含边界值）。
4. 报警触发后是否存在可执行的 continue/retry 闭环。
5. 手动模式是否支持逐点“打压/确认/采集/重采”。
6. 结束后阀门是否可通过设备卡片切回安全状态，且打压设备停止。
7. 前端展示的步骤与后端状态机是否一一对应。

## Design Context

### Users

Small engineering teams in testing labs (wind tunnel and measurement environments). They use DAQ Professional for real-time data acquisition, hardware calibration, motion control, and waveform monitoring. Users are typically seated at the workstation, interacting directly with the desktop app. Their primary job is to run precise, high-frequency experiments, monitor device health, and react quickly to anomalies. The interface must support both deep-focus configuration and rapid situational awareness.

### Brand Personality

**Technical · Clean · Commanding**

- **Voice / Tone**: Direct, unambiguous, data-forward. No marketing fluff.
- **Emotional goals**: Confidence in precision, calm during normal operation, urgent clarity during alarms. The UI should feel like a professional instrument panel — trustworthy and in control.
- **Positioning**: The software is a tool, not a destination. Every pixel serves measurement or control.

### Aesthetic Direction

- **Visual tone**: Flat industrial, zero decorative gradients or shadows. Pure utility.
- **Theme**: Dark-mode-first (`Industrial Deep Graphite` #0c0e12–#232838) with a functional light mode (`Warm Concrete` #f5f5f0).
- **References**: The existing token system (`color.css`, `typography.css`, `spacing.css`, `glass.css`) and `ui-spec-live-acquisition.md` already define the look — high-density dashboards, 1px separators, monospace data displays, glass overlays for modals/drawers.
- **Anti-references**: Legacy cluttered SCADA interfaces; consumer SaaS playful aesthetics (rounded cards, heavy shadows, gradients). Keep it commanding, not cute.
- **Typography**: Funnel Sans / Inter for UI labels and body; Geist Mono for all numeric data, time displays, and channel identifiers. CJK fallbacks (`Microsoft YaHei UI`, `PingFang SC`) are required.
- **Motion**: Fast and functional (120ms–260ms). No decorative motion. Status pulses and alarm flashes are the only continuous animations.

### Design Principles

1. **Data is the UI** — Numerical values, status indicators, and waveforms are the visual center. Decorative elements are prohibited.
2. **Status is feedback** — Every operational state (running, idle, warning, error) must be instantly recognizable at a glance through color, shape, and motion.
3. **Density over whitespace** — Information density is prioritized. Modules are separated by 1px lines, not large gutters.
4. **3-meter readability** — Minimum contrast ratios (WCAG AA+), large mono numerals for KPIs and tables, and distinct non-color status shapes for color-blind safety.
5. **Motion serves function only** — Animations indicate state change (alarm flash, log entry slide) or provide tactile feedback (button press). No ambient or decorative motion.

## Waveform / Chart Specifications

- **Engine**: ECharts 6 + vue-echarts, custom dark theme
- **Grid**: Major `rgba(255,255,255,0.06)` every 50px; Minor `rgba(255,255,255,0.02)` every 10px
- **Line width**: 1.5px (active), 1px (inactive/frozen)
- **Sample points**: Hidden by default; show 3px dots at zoom-to-point level
- **Idle area**: Gray dashed line `rgba(148,163,184,0.3)`
- **Animation**: Disabled for real-time data (`animation: false`)
- **Scroll window**: Default 1000 points, configurable to 5000
- **Modes**: Overlay (shared Y) / Split (independent subplots)
- **Cursors**: Single (`C`) — t + instantaneous values; Dual (`D`) — Δt, ΔV, freq, period
- **Zoom**: Mouse wheel (X-axis), Shift + drag box select; Pan: middle-mouse or Ctrl + drag; Reset: double-click or `R`

## State Management (Pinia Stores)

| Store | Responsibility |
|---|---|
| `deviceStore` | Device management, channel data, chart selection, tare |
| `motionStore` | Motion controller CRUD, status polling |
| `calibrationStore` | Calibration task lifecycle |
| `traversalStore` | Traversal test lifecycle |
| `storageStore` | Recording settings and status |
| `themeStore` | Theme toggle (`dark` / `light`), persisted to `localStorage` |
| `i18nStore` | Internationalization (`zh` / `en`) |
| `feedbackStore` | Toast and confirmation dialogs |

**Theme switching mechanism**: `document.documentElement.dataset.theme = 'light' | 'dark'`; CSS overrides via `:root[data-theme='light']`.

## Error & Empty States

### Device States
| State | Visual | Behavior |
|---|---|---|
| Online | Green dot + "Online" | Normal data display |
| Offline | Gray dot + "Offline" | Data shows `--`, actions disabled |
| Error | Red dot + error message | Last known value (gray) + error description |
| Connecting | Yellow pulse dot + "Connecting..." | Data shows `...`, 3s timeout to offline |

### Empty States
| Scenario | Display |
|---|---|
| No device | Illustration + "请添加设备" + add button |
| No data | Channel card shows `--` + "等待数据" |
| No calibration record | "尚无校准数据" + start calibration button |

### Feedback Levels
| Level | Component | Behavior |
|---|---|---|
| Info | UiToast (info) | Bottom-right, 3s auto-dismiss |
| Warning | UiToast (warning) | Bottom-right, 5s auto-dismiss |
| Error | UiToast (error) | Bottom-right, manual close |
| Critical | UiConfirmDialog | Modal, requires confirmation (disconnect, acquisition failure) |

## Notes for AI Agents

- Always respect the 4px grid and existing CSS custom properties.
- Prefer `naive-ui` primitives only when they match the flat industrial aesthetic; otherwise build custom components using the token system.
- All new components should support both `dark` and `light` themes via `data-theme` attribute.
- Status indicators must combine **color + shape** (dot, triangle, square) to be color-blind safe.
- Avoid adding decorative animations, ambient gradients, or playful micro-interactions.
- **No responsive breakpoints** — this is a fixed desktop layout (min 1280×720, target 1920×1080).
- **Glassmorphism is restricted** to Header/Footer only; main content panels use solid backgrounds for readability and performance.
- **Frontend owns display only** — all business logic (calibration algorithms, measurement processing, device control) lives in the Rust backend.
- When creating new projects, follow the token structure in `styles/tokens/` and component hierarchy in `DESIGN.md` Section 12.

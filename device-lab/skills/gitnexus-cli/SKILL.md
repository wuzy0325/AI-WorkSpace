# GitNexus CLI Commands

Commands use the project-local runner `node .gitnexus/run.cjs` (auto-generated by `gitnexus analyze`). It auto-selects an available runner (global `gitnexus`, else `pnpm dlx`, else `npx`). Fall back to `npx gitnexus` if the local runner is absent.

> **First time / no local runner yet:** Run `npx gitnexus analyze` from the project root. On **npm 11.x**, if `npx` crashes (`node.target is null`), use `npm i -g gitnexus && gitnexus analyze` or `pnpm --allow-build=@ladybugdb/core --allow-build=gitnexus --allow-build=tree-sitter dlx gitnexus@latest analyze`.

## Commands

### analyze — Build or refresh the index

```bash
node .gitnexus/run.cjs analyze
# or fallback:
npx gitnexus analyze
```

Run from the project root. Parses all source files, builds the knowledge graph, writes it to `.gitnexus/`, and generates CLAUDE.md / AGENTS.md context files.

| Flag             | Effect                                                         |
| -----------------| -------------------------------------------------------------- |
| `--force`        | Force full re-index even if up to date                         |
| `--embeddings`   | Enable embedding generation for semantic search (off by default)|
| `--drop-embeddings` | Drop existing embeddings on rebuild                          |

**When to run:** First time in a project, after major code changes, or when the MCP context warns the index is stale. OpenCode/Trae/Claude Code/Cursor/Codex all benefit from a fresh index.

### status — Check index freshness

```bash
node .gitnexus/run.cjs status
```

Shows whether the current repo has a GitNexus index, when last updated, symbol/relationship counts.

### clean — Delete the index

```bash
node .gitnexus/run.cjs clean
```

Deletes `.gitnexus/` and unregisters the repo.

| Flag      | Effect                                  |
| --------- | --------------------------------------- |
| `--force` | Skip confirmation prompt                |
| `--all`   | Clean all indexed repos, not just current |

### wiki — Generate documentation from the graph

```bash
node .gitnexus/run.cjs wiki
```

Requires an LLM API key (saved on first use).

| Flag                | Effect                                    |
| ------------------- | ----------------------------------------- |
| `--model <model>`   | LLM model (default: minimax/minimax-m2.5) |
| `--base-url <url>`  | LLM API base URL                          |
| `--api-key <key>`   | LLM API key                               |
| `--concurrency <n>` | Parallel LLM calls (default: 3)           |
| `--gist`            | Publish wiki as a public GitHub Gist      |

### list — Show all indexed repos

```bash
node .gitnexus/run.cjs list
```

Lists all repos in `~/.gitnexus/registry.json`. The MCP `gitnexus_list_repos` tool provides the same information.

## After Indexing

1. **Read `gitnexus://repo/{name}/context`** to verify the index loaded
2. Use the other GitNexus skills (`exploring`, `debugging`, `impact-analysis`, `refactoring`) for your task

## Troubleshooting

- **"Not inside a git repository"**: Run from a directory inside a git repo
- **Index is stale after re-analyzing**: Restart your AI coding assistant (Claude Code / OpenCode / Trae / Cursor) to reload the MCP server
- **Embeddings slow**: Omit `--embeddings` (off by default) or set `OPENAI_API_KEY` for faster API-based embedding
- **`node .gitnexus/run.cjs` not found**: Run `npx gitnexus analyze` to generate the local runner first

# Modbus TCP 协议栈（`protocol/modbus`）

全 workspace 首个 Modbus 实现，供 DAQ-T1602 温度扫描阀驱动使用。
纯手写 MBAP + PDU（Go `net` 标准库，零第三方依赖），只实现设备用到的
最小功能子集：FC3 读 Holding、FC4 读 Input、FC6 写单寄存器。

> 本文件参数全部来自真机实测（2026-08-12，设备 192.168.3.201:502），
> 详见 `projects/wind-daq/docs/specs/spec-daq-t1602.md` §Protocol。

## 设备寄存器映射（DAQ-T1602）

T1602 机内含 2 张独立采集卡，每卡 8 通道，合并对外为 16 通道单设备。
两张卡共用一条 Modbus TCP 连接，通过 Unit ID 区分（卡1=1，卡2=2）。

| 用途 | 功能码 | 寄存器类型 | 地址 | 每卡数量 | Unit ID | 卡 |
|---|---|---|---|---|---|---|
| 热电偶类型 | FC3 (0x03) | Holding | 200~207 | 8 | 1 | 卡1 CH0~7 |
| 热电偶类型 | FC3 | Holding | 200~207 | 8 | 2 | 卡2 CH0~7 |
| 采集数据 | FC4 (0x04) | Input | 0~7 | 8 | 1 | 卡1 CH0~7 |
| 采集数据 | FC4 | Input | 0~7 | 8 | 2 | 卡2 CH0~7 |

## 关键实测参数

| 项 | 实测值 |
|---|---|
| 端口 | 502 |
| 单次读上限 | 8 寄存器（读 9+ 返回异常码 2） |
| 单请求 RTT | 固定 ~103ms（设备 100ms 响应周期，固件串行处理） |
| 双卡完整采集 | ~4.9 Hz（2 请求/帧，理论下限 ~206ms/帧） |
| 请求并行 | 无效（固件串行排队） |
| 类型寄存器现值 | 16 通道全部 0x0002（T 型） |

## 连接模型

- **单 TCP 连接 + Unit ID 复用**：Modbus TCP 的 Unit ID 字段本身就是为单连接
  寻址多从站设计的；实测证明固件串行排队、多连接并行无效，因此驱动只建立
  **一条** 到 `IP:502` 的连接，卡1/卡2 通过 Unit ID 1/2 区分。
- **Transaction ID**：请求侧自增（uint16 回绕），响应必须回显校验；
  ID 不匹配的响应丢弃并按超时处理（防止串帧）。
- **响应超时**：读/写请求超时固定 1s（`ResponseTimeout`，远大于实测 103ms RTT）；
  超时即判定连接损坏，走 ADR-009 owner `Close()` 路径，连接不可复用。
- **串行化**：同一连接上所有请求严格串行（单 in-flight，`roundTrip` 全程持锁），
  禁止流水线——与固件行为一致，也简化帧边界切割。

## 帧格式

- MBAP：事务 ID(2B) + 协议 ID(2B=0) + 长度(2B) + 单元 ID(1B)
- FC3/FC4 请求 PDU：`FC(1B) + 起始地址(2B) + 数量(2B)`
- FC6 写单寄存器 PDU：`FC(1B=0x06) + 地址(2B) + 值(2B)`；正常响应原样回显请求 PDU
- 读响应：`FC + 字节数(1B) + 数据(N×2B，大端)`
- 异常响应：`FC|0x80 + 异常码(1B)` → `*ExceptionError`（业务错误，不毒化连接）
- **Max ADU**：读响应最长 8×2+9 = 25 字节；帧边界按 MBAP length 字段精确切割

## 错误模型

| 错误 | 含义 | 连接处置 |
|---|---|---|
| `*ExceptionError` | 设备异常响应（FC\|0x80 + 异常码） | 业务错误，连接可复用 |
| `ErrConnBroken` | 超时 / Transaction ID 不回显 / I/O 错误 / 帧格式非法 | 已 Close，禁止复用，必须重连 |
| 参数校验错误 | count 越界 [1,8] 等客户端错误 | 连接可复用 |

## ADR-009（Windows 网络约束）

- `SetDeadline` 仅作软超时；每个请求由独立 watchdog（`protocol.WatchdogClose`）
  在超时后直接 `conn.Close()` 解除阻塞 I/O，不依赖 deadline 在故障电脑上生效。
- watchdog 关闭的连接不可复用；`fail`/`poison` 路径经 `protocol.AbortConnection`
  （CloseWrite FIN + Close）后台执行，避免故障电脑上 Close 挂起阻塞。
- 测试含"忽略所有 deadline、只在 Close 后返回"的连接 double
  （`deadlineIgnoringConn`，见 `modbus_test.go`）。

## Type Code 枚举与换算

量程表为用户提供（2026-08-13），共 10 行，行号 = Type Code，8/9 行未使用：

| Type Code | 热电偶 | 量程 [min,max] ℃ |
|---|---|---|
| 0 | J | (-50, 50) |
| 1 | K | (0, 1200) |
| 2 | T | (0, 1300) |
| 3 | E | (-200, 400) |
| 4 | R | (0, 1000) |
| 5 | S | (0, 1700) |
| 6 | B | (0, 1768) |
| 7 | N | (0, 1800) |
| 8 | （未使用） | (-200, 800) |
| 9 | （未使用） | (-2000, 1000) |

换算公式（用户确认，与 LabVIEW 逆向一致）：

```
物理温度(℃) = raw / 65535 × (RangeMax - RangeMin) + RangeMin
```

**raw = 0 表示通道未接入热电偶**（开路输出 0，2026-08-13 用户确认），不是量程
下限温度：驱动 `t1602RawToTemp` 返回 NaN，上层序列化为 null，UI 显示 "--"。

真机验证（2026-08-13）：K 型通道 raw 1513 → 27.7℃，与室温吻合；T 型配置下
raw 1369 → 27.2℃，交叉一致；无信号通道 raw=0 → NaN（UI 显示 "--"）。
类型寄存器可运行时改写（FC6 写 + 读回校验通过，
改写后 raw 随类型变化，确认类型码参与设备内部换算）。

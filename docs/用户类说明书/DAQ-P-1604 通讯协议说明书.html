DAQ-P-1604 通讯协议说明书

16 通道压力 + 大气压力 + 大气温度 · TCP/IP + UDP 发现 · 自定义二进制协议

适用范围本文档面向设备集成开发工程师，详细说明 DAQ-P-1604 的通讯协议、命令格式、数据帧结构和开发注意事项，帮助客户快速完成设备驱动开发和系统集成。

1.1 连接流程

1. 创建 TCP Socket，连接 host:port（默认 192.168.3.101:9000），超时 5s 2. 注册 socket 'data' 事件监听 3. 连接成功后立即发送 "w1601" → 启用 2 字节大端长度前缀模式 4. 后续所有命令通过 sendCommand() 收发 5. 可选：发送 "q00" 读取设备型号确认连接
⚠️ 关键w1601 必须在任何其他命令之前发送，确保后续所有响应都带长度前缀。否则无法正确拆包。

1.2 生命周期

┌──────────────┐ connect() ┌──────────────┐ startAcquisition() ┌────────────┐ │ Disconnected │ ────────────────→ │ Connected │ ────────────────────────→ │ Acquiring │ │ │ ←──────────────── │ │ ←──────────────────────── │ │ └──────────────┘ disconnect() └──────────────┘ stopAcquisition() └────────────┘ ↑ │ │ └────── handleDisconnect() ───────┴──────────── 异常退出 readLoop ────────┘
  1. 构造驱动 — 传入 DeviceConfig + ChannelConfig[]
  2. 注册回调 — onData(payload) 接收解析后的数据
  3. 连接 — TCP 连接 + 自动发送 w1601
  4. 启动采集 — 内部执行 c 00(配置) → c 05(返回内容) → c 01(启动)
  5. 停止采集 — c 02
  6. 断开 — 关闭 TCP 连接

2. 通讯协议基础

2.1 长度前缀模式（w1601）

所有命令响应前 2 字节为大端无符号 16 位长度前缀（含自身 2 字节）。连接后必须发送 w1601 启用。

byte 0lenHi
byte 1lenLo
byte 2 ~ byte(N-1)payload（长度 = len − 2）
字段长度格式说明
lenHi / lenLo2 字节uint16 BE整帧长度（含自身），最小值 2
payloadlen − 2 字节ASCII 或二进制实际响应数据
示例收到 00 05 41 0D 0A → len=5，payload = "A\r\n"（成功响应）

2.2 命令响应码

响应长度含义
A1 字节成功（Acknowledge）
N013 字节无效命令
N033 字节输入缓冲区溢出
N043 字节收到无效的 ASCII 字符
N053 字节数据字段错误
N073 字节设置的限定值无效
N083 字节扫描器错误，无效的参数
N0A3 字节校准阀不在要求的阀位上
⚠️所有以 N 开头的响应均为错误。命令以纯 ASCII 发送（无换行符）。

4. 数据帧协议

4.1 二进制帧结构（配置 w1601 + c 05 1 0810 后）

以下为不含 2 字节长度前缀的帧负载格式：

byte 00x01
byte 1~2seqNum (uint16 BE)
byte 3~4保留
byte 5~7618 × float32 BE 通道值
偏移大小内容
01固定 0x01
12帧序号（uint16 大端）
32保留
54 × 18 = 7218 个 float32 大端通道值
⚠️ 通道顺序陷阱
Index 0..15（前 16 个 float）：CH16, CH15, CH14, ..., CH1 — 硬件的返回是逆序的！
Index 16：大气压力（CH17）
Index 17：大气温度（CH18）

必须在驱动层反转：values[0..15].reverse() 后得到 CH1..CH16 正序。

完整帧示例（含长度前缀，共 79 字节）

// 2B 长度前缀 (BE, 含自身) = 79 (0x004F)
00 4F

// 帧头部 5B
01     // 固定 0x01
00 01  // 帧序号 = 1
00 00  // 保留

// 通道数据 72B (18 × float32 BE)
42 20 00 00  // CH16 = 40.0
00 00 00 00  // CH15 = 0.0
   ⋮
41 20 00 00  // CH1 = 10.0
44 70 00 00  // 大气压力 = 960.0 Pa
41 A0 00 00  // 大气温度 = 20.0 ℃

4.2 ASCII 帧判定

检查 payload 前 64 字节：若全部为可打印 ASCII（0x20-0x7E）或 CR/LF，则判定为 ASCII 帧。

  • ASCII 帧 → 放入 pendingResponses FIFO 队列，匹配 sendCommand Promise
  • 二进制帧 → 调用 handleStreamFrame 解析

4.3 解析步骤

1. 读取前 2 字节得到 frameLength（uint16 BE）
2. 等待接收缓冲区 ≥ frameLength
3. 提取 frame[2..frameLength] 为负载
4. 区分 ASCII / 二进制帧
5. 二进制帧：跳过 5 字节头部，每 4 字节读 float32BE，共 18 个
6. 前 16 个值反转（设备发 CH16..CH1 → 转为 CH1..CH16）
7. 第 17 = 大气压力，第 18 = 大气温度
function parseBinaryFrame(payload):
    seqNum  = payload.readUInt16BE(1)
    values  = []
    for i in 0..18:
        values.append(payload.readFloat32BE(5 + i * 4))
    pressures = values[0..16].reverse()  // 反转前 16 个
    pAtm     = values[16]                 // CH17 大气压
    tAtm     = values[17]                 // CH18 温度
    return { pressures, pAtm, tAtm, seqNum }

DataPayload 输出格式

{
  deviceId: "p1604-01",          // 设备 ID
  timestamp: 1781664000000,       // 本地时间戳 Date.now()
  channels: [10.0, 0.0, ...],      // 仅包含 enabled 通道的数值
  channelIndices: [0, 1, ...]     // 对应 enabled 通道的索引
}

4.4 轮询模式（备用）

rFFFF0 命令作为调试备用，主采集路径使用数据流模式。
  • 返回 ASCII 格式，空格分隔
  • 顺序：CH16 → CH1（逆序，与流帧一致）
  • 解析：parts[i] → 物理通道 16 - i
  • 不返回 CH17/CH18（大气压/温度需要额外命令）

7. 开发示例

7.1 连接与采集

function connect(host, port=9000):
    socket = tcp.connect(host, port, timeout=5000)
    resp = sendCommand("w1601", timeout=1000)
    if resp startsWith "N":
        log.warn("Failed to enable length prefix")
    return true

function startAcquisition(periodMs=100):
    resp = sendCommand("c 00 1 FFFF 1 {periodMs} 7 0")
    assert resp == "A"
    resp = sendCommand("c 05 1 0810")
    assert resp == "A"
    resp = sendCommand("c 01 1")
    assert resp == "A"

function stopAcquisition():
    sendCommand("c 02 1")   // best effort

function readFrame(buffer):
    length = buffer.readUInt16BE(0)
    if buffer.size < length: return null
    payload = buffer[2..length]
    buffer.consume(length)
    if isASCII(payload):
        return asciiResponse(payload)
    else:
        return parseBinaryFrame(payload)

7.2 校准流程

function calibrateZeroFullscale(targetPressure):
    sendCommand("w0C01")                          // 阀门 → 校准位
    sendCommand("C 04 FFFF", timeout=10000)     // 零点校准
    sendCommand("C 05 FFFF {targetPressure:.6f}", timeout=10000)
    sendCommand("w08")                            // 保存零位
    sendCommand("w09")                            // 保存增益
    sendCommand("w0C00")                          // 阀门 → 测量位

function calibrateMultipoint(pressurePoints, avgPerPoint=10):
    n = pressurePoints.length
    sendCommand("C 00 FFFF {n} 1 {avgPerPoint}", timeout=5000)
    for i, target in enumerate(pressurePoints):
        sendCommand("C 01 {i} {target:.2f}", timeout=10000)
    sendCommand("C 02", timeout=10000)            // 拟合
    sendCommand("C 03", timeout=5000)             // 结束
    sendCommand("w08")
    sendCommand("w09")

7.3 UDP 设备发现

function scanDevices(timeoutMs=3000):
    udp.bind(port=7001)
    udp.setBroadcast(true)
    addrs = getBroadcastAddresses()
    for addr in addrs:
        udp.send("psi9000", addr, port=7000)

    devices = []
    while not timedOut:
        msg = udp.receive()
        parts = msg.split(",")
        if parts.length >= 9:
            devices.append({
                ip:       parts[0],
                mac:      parts[1],
                serial:   parts[3],
                firmware: parts[4],
                port:     int(parts[7]),
                mask:     parts[8],
                gateway:  parts[9]
            })
    return devices

8. 错误处理

连接错误检测

function isConnectionFault(err):
    keywords = [
        "i/o timeout",
        "broken pipe",
        "connection reset by peer",
        "device disconnected",
        "EOF"
    ]
    return any(keywords where err.message.contains(keyword))

超时策略

场景超时说明
TCP 连接5000 ms建立连接
普通命令响应5000 ms等待设备回复
校准命令10000 ms校准操作物理时间较长
流数据间隔警告1000 ms超过此间隔发出日志警告

重连机制

  • 指数退避：min(2^attempt × baseDelay, maxDelay)
  • Socket 异常关闭 → 清空 recvBuffer 和 pendingResponses
  • 不支持自动重连时，通过回调通知上层

9. 开发注意事项

#注意点
1连接后必须发 w1601：启用长度前缀才能正确拆包，且必须作为第一条命令
2通道倒序：rFFFF0 和数据流均为 CH16..CH1，必须反转为 CH1..CH16
3校准前切阀：w0C01 → 校准位，完成后 w0C00 → 测量位
4校准后保存：w08 + w09 写入非易失存储，否则断电丢失
5不建议发 c 06：部分固件返回 N05
6帧长度含自身：length − 2 = 实际负载数据长度。如果 len < 2 视为异常
7所有响应以 N 开头为错误：收到 N01~N0A 需根据错误码处理
8单位同步失败不阻塞连接：catch 后仅 warn，继续后续流程
9流数据帧间隔超阈值：超过 STREAM_GAP_WARN_MS(1000ms) 发出警告日志
10ASCII 命令纯文本：命令以纯 ASCII 发送，无换行符；响应带长度前缀

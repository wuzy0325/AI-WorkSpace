# 高质量代码结构规范

> 本文承载通用编码规范：文件结构、命名、注释、写法、复用。
> 架构选型（六边形 vs 三层）、依赖边界、硬约束由 [CLAUDE.md](../../CLAUDE.md) 定义，本文不重复。
> 前端专项规则见 [frontend-ai-rules.zh-CN.md](frontend-ai-rules.zh-CN.md)。

---

## 一、文件 & 代码块结构规范

### 单文件职责唯一

一个文件只做一件事：一个路由、一个服务、一类工具。

### 文件长度限制

常规文件控制在 **300～500 行**内。超长文件强制拆分——AI 超长上下文极易理解错乱。

### 禁止 dead code

未使用的私有符号（func / type / field / var / const）必须直接删除，不得保留在源码中。

- **检测工具**：`staticcheck -checks U1000`
- **集成位置**：`scripts/validate-structure.ps1` § 2f（pre-submit 流程自动执行）
- **豁免清单**：`scripts/staticcheck-u1000-waivers.txt` 仅用于过渡期管理预存 dead code
- **新增 dead code 不得加入豁免清单**——必须直接删除源码
- **维护原则**：清理 dead code 后，必须同步删除豁免清单中对应行
- **背景**：人工 code review 对私有未导出符号的覆盖天然不全，曾漏掉 3 处 dead code；改用静态分析兜底

### 代码块顺序固定

推荐固定顺序，AI 阅读成本极低：

1. 包导入/依赖
2. 常量/枚举/全局配置
3. 类型/结构体定义
4. 中间件/钩子
5. 对外暴露方法/接口
6. 内部私有方法

### 函数/方法短小化

- 单个函数不超过 **50 行**
- 复杂逻辑拆分为子函数，拒绝巨型函数

## 二、命名规范

### 命名语义化

禁止缩写、拼音、乱简写：`userLoginCheck` ✅ / `usrChk` ❌

### 统一命名风格

| 场景 | 规范 |
|------|------|
| 前端 TS/JS | 小驼峰 `camelCase` |
| Go/Python | 蛇形 `snake_case` |
| 类/结构体 | 大驼峰 `PascalCase` |

### 变量用途显性化

- 布尔值统一前缀：`is` / `has` / `enable` / `allow`
- 临时变量、缓存变量、返回变量命名区分开

### 禁止魔法值

所有 0、1、状态码、错误码、固定文案，全部定义为常量。

## 三、注释 & 文档规范

### 必须写模块级注释

每个文件顶部说明当前文件作用、依赖、业务场景。

### 所有对外方法必须写文档注释

标注：入参含义、出参结构、异常场景、使用限制。

### 复杂业务逻辑加段落注释

不是注释每一行，而是注释**为什么这么写、业务规则**。

### Bug 遗留/临时方案标记

统一标记：`// TODO:` / `// FIXME:` / `// NOTE:`

AI 可直接检索批量处理遗留问题。

## 四、逻辑与写法规范

### 拒绝深层嵌套

嵌套 `if`/`for` 不超过 **3 层**，多用提前 `return` 扁平化代码。

### 纯函数优先

通用工具方法：无副作用、不修改入参、依赖外部资源越少越好。

### 错误处理统一规范

- 全局统一错误码、统一返回格式
- 禁止吞异常、裸 `try/catch` 不处理

### 参数校验前置

所有接口入参、函数入参，第一行先校验。

### 避免隐式逻辑

不要靠全局变量、上下文隐式传参，尽量显式传参。

---

## 五、复用 & 抽象规范

### 重复代码必须抽离

重复出现 **3 次以上**逻辑，抽取为工具函数/公共方法。

### 通用能力抽象封装

缓存、OSS、短信、数据库、第三方请求统一封装 SDK。

### 业务规则集中管理

活动规则、权限规则、计算公式统一放在单独的 `rule` 模块。

---

## 六、AI 友好专属增强规则

### 固定编码风格 & 格式化

开启 ESLint / Prettier / `gofmt` 强制格式化，代码风格统一。

### 依赖版本固定

`package.json` / `go.mod` / `requirements` 锁定版本，避免 AI 升级依赖炸库。

### 最小权限导出

只暴露必要方法，私有逻辑内部隐藏，防止 AI 乱调用内部函数。

### 关键流程可追踪

核心链路加日志、埋点，AI 排错时可快速还原执行流程。

### 避免奇葩语法 & 过度简写

少用三元嵌套、复杂链式调用、语法糖堆砌，保持写法朴素。

---

## 七、落地极简执行版

1. **定目录** — 全项目统一目录结构，AI 不再猜位置（架构选型见 [CLAUDE.md](../../CLAUDE.md)）
2. **限行数** — 单文件 ≤ 500 行，单函数 ≤ 50 行
3. **统一命名** — 语义化 + 常量替代魔法值
4. **分层解耦** — 禁止跨层乱写逻辑，依赖接口而非实现
5. **文档注释** — 对外方法必写，复杂逻辑写"为什么"
6. **错误统一** — 全局错误码 + 统一返回格式 + 参数校验前置
7. **格式化 + Lint** — 开启强制格式化，风格统一

## 为什么这套结构对 AI 特别有用？

| 原则 | 对 AI 的帮助 |
|------|-------------|
| 结构固定 | AI 不用猜测代码位置，改 Bug、加功能精准定位 |
| 拆分细致 | AI 单次只需要理解小片段，不会上下文过载 |
| 语义命名 + 注释 | AI 读懂业务意图，不只读懂代码语法 |
| 解耦分层 | AI 修改某一块逻辑，不会误伤其他模块 |

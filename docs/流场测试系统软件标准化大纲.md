## 1 范围

### 1.1 编制依据
- 通用软件工程标准：GB/T 8566《信息技术 软件生存周期过程》、GB/T 25000.51 / ISO/IEC 25010 系统与软件质量要求、GB/T 8567《计算机软件文档编制规范》；
- NI/LabVIEW 工程规范：LabVIEW 编程风格指南（NI 官方风格建议 / 《The LabVIEW Style Book》）、VI Analyzer 检查项配置、仪器控制 SCPI（IEEE 488.2 / IEC 60488）、VISA、IVI、NI-DAQmx 编程规范；
- 本项目内部规范：《流场测试系统 LabVIEW 编码与目录规范》《架构决策记录（ADR）》《版本管理办法》。

### 1.2 适用范围
本大纲适用于本 LabVIEW 软件的需求、设计、实现（VI 开发）、测试、验收与交付全过程标准化工作，覆盖：
- 风洞/流场试验数据采集与实时监控（NI-DAQmx）；
- 探针（三孔/五孔/七孔）校准与流场参数解算；
- 压力扫描阀、压力控制器、采集卡、运动控制器等设备通信与控制（VISA/SCPI、NI-DAQmx、运动控制）；
- 试验数据存储（TDMS/CSV）、遍历（traversal）、回放、报告生成与人机交互（前面板/子面板）。

## 2 概述

### 2.1 任务来源
本软件依据《流场测试系统研制任务书》开展研制，本版本目标为完成风洞流场试验数据采集、探针解算、设备控制、数据存储与报告的完整功能交付并通过标准化审查。

### 2.2 产品用途与组成
本软件是面向风洞试验室的工业桌面工具，用于配置硬件、运行试验、监视实时数据并分析结果。采用 **LabVIEW** 图形化开发环境，结构为 LabVIEW 项目（.lvproj）+ 项目库（.lvlib）+ 类（.lvclass）+ 各功能 VI。软件由以下模块组成：
- **采集与实时监控模块**：基于 NI-DAQmx 任务与队列式消息处理（QMH）+ 生产者/消费者架构完成实时采集、流式显示与数据缓冲；
- **校准与解算模块**：探针校准数据库 + 插值解算 VI（总压/静压/速度/马赫数/气流角度）；
- **设备通信与控制模块**：基于 VISA/SCPI 的仪器驱动 VI（压力扫描阀、压力控制器等）、NI-DAQmx 驱动、运动控制 VI；
- **运动与遍历模块**：运动控制 + 遍历路径/检查点序列 VI；
- **存储与报告模块**：TDMS/CSV 文件 I/O、报告生成（HTML/Excel/PDF）；
- **人机交互模块**：前面板/子面板组成的仪表盘与各功能视图（校准/设备/运动/遍历/存储/日志）。

### 2.3 对标准化的要求
在架构边界、接口契约、VI 文档、编码风格、测试、配置管理、错误处理等方面满足本大纲约定的工程标准，实现过程规范化、模块可复用、接口统一、质量可验证。

## 3 标准化目标

- **定性目标**：贯彻本大纲约定的架构与编码标准，保证 UI 与业务逻辑分离、模块可复用、设备接口统一、VI 文档与代码技术状态一致。
- **定量目标**：
  - VI Analyzer 检查在提交前及持续集成中 **100%** 通过；
  - 关键模块单元测试通过率 **100%**；
  - VI 文档覆盖率（VI 描述 / 连线板 / 错误簇处理）达 **≥95%**；
  - 标准化问题闭环率 **100%**。

## 4 标准实施要求

### 4.1 一般要求
1. 标准贯彻以本大纲 + 项目编码规范为准；
2. 重大架构/目录调整须评审留痕（架构决策记录 ADR）；
3. 所有标准相关改动经评审、会签、批准后实施，按配置管理程序进行；
4. 对标准实施过程进行监督：VI Analyzer + 单元测试 + 代码评审三重把关；
5. 实施中出现的问题按"提出—分析—处理—归零—闭环"程序解决（见附录 B）。

### 4.2 重大标准实施要求（须专项方案并报审）
- **架构边界**：UI 与业务逻辑分离，采集/校准逻辑不得堆砌在单一 VI；采用硬件抽象层（HAL，以 LabVIEW 类 + 动态分发实现），新设备 = 新类实现、核心零改动；
- **并行与错误处理**：统一采用队列式消息处理（QMH）+ 生产者/消费者标准并行架构；错误簇（error cluster）全程连线，禁止静默丢弃；
- **仪器控制统一**：设备通信统一基于 VISA/SCPI（遵循 IEEE 488.2），同类设备按统一驱动接口契约实现，便于互换；
- **生产构建规范**：经 Application Builder 生成独立可执行文件（.exe）+ 安装包（.msi），禁用调试、嵌入版本信息。

### 4.4 复用与第三方件选用范围（LabVIEW 侧）
- 优先封装为项目库（.lvlib）/类（.lvclass）/打包项目库（.lvlibp）以提升复用；
- 两个及以上功能复用的逻辑须抽为共享库，禁止在各处复制 VI；
- 第三方工具包（VIPM 包、NI 工具包、厂商仪器驱动）须登记并锁定版本；
- 探针解算等算法以单一权威库实现，禁止多份拷贝（单一真相原则）。

## 5 软件通用化、系列化、组合化及接口、互换性要求

- **通用化**：统一错误处理（错误簇）、统一日志、统一配置读写、统一前面板风格与子面板框架；
- **系列化**：不同探针类型（三孔/五孔/七孔）、不同采集/控制设备经统一驱动接口（LabVIEW 类动态分发）扩展，不改动核心解算逻辑；
- **组合化（CBB）**：校准、采集、运动、遍历、存储、报告封装为可组合的项目库/模块，经主程序编排；
- **接口要求**：仪器通信以 VISA/SCPI 契约为准；数据存储以 TDMS/CSV 契约为准；UI 经明确定义的 VI 接口访问业务逻辑，禁止前面板直接操作硬件；
- **互换性**：同类设备驱动按统一接口契约实现，更换设备不影响上层；新设备 = 新类，零核心改动。

## 7 图样和技术文件要求

### 7.1 完整性、正确性、统一性
- VI 文档齐全：VI 描述、连线板（连接器）、控件/常量说明、错误簇处理符合风格指南；
- 文档内容与代码/技术状态一致，版本受控（VI 版本、项目版本、变更日志）；
- 术语、命名、单位（压力单位、精度、通道号、列序）在全项目统一；数据文件结构由统一读写 VI 定义并经测试保护。

### 7.2 管理要求
- 所有 VI 与文档纳入版本控制，按配置管理计划受控（LabVIEW 二进制 VI 使用 LVCompare/LVMerge 差异合并工具）；
- 阶段评审前完成 VI Analyzer 检查与标准化审查并出具结论。
